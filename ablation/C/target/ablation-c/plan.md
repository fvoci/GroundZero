# Experiment C, pre-change protocol

Fixed baseline: 22ad80ee205332e3ef1ffd8f64f783789955921b. See identity.txt for exact toolchain and lock hashes. No tracked changes at recording time.

Hypothesis: writing the first sixteen digest bytes as lowercase hexadecimal directly into the final capacity-34 quoted String eliminates sixteen temporary per-byte strings and the intermediate collected string. Domain prefix, user, zero delimiter, body, SHA-256, truncation, quotes and public function signature stay identical. No parsing, permission, transaction, response construction or error path changes.

Acceptance: byte equivalence for fixed known vectors and deterministic binary inputs/users; existing cache unit tests pass; direct formatting median cost improves by at least 10% with paired improvements in at least 90% of rounds across two runs. Total hash timings are reported separately, including noise; no end-to-end latency claim. Reject performance hypothesis if formatting improvement is inconsistent; identify maintenance-only outcome separately. Full service integration and repository checks are coordinator-owned and NOT RUN here unless a slot/services are explicitly assigned.

Measurement: optimized standalone Rust executable, same compiler and existing locked sha2 library; baseline and candidate in same process, warmed, alternating AB/BA per round, 31 rounds, three distinct fixed users, bodies empty/256 bytes/1 MiB, separate precomputed-digest formatting case. Black-box inputs and outputs. Raw nanoseconds per operation, paired ratios, p10/p50/p90 and run-to-run comparison. Synthetic CPU microbenchmark only; allocation removal inferred from source, not allocation instrumentation.

Boundary: documents::representation serializes before strong_etag; get authenticates and load_with_access commits before comparison; save validates, checks permission, locks, tests idempotent replay, then If-Match, revision, no-op and mutation. document_reply, conflict_reply, save and revisions restore use the same representation. Pure strong_etag has no DB/event/audit calls; identical returned bytes preserve all branch conditions and response ETag fields. Caller code and SQL remain untouched.
