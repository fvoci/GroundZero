# fvoci 결정 기록

최초 작성: 2026-10-17. 정책 번호와 명시된 승인·대체·보류를 유지하는 색인이다. 저장소는 이미 구현·검사 설정을 갖추고 있다. **정책 확정, 구현 완료, 특정 SHA·환경의 검증 완료는 별개**다. 현재 개발 계약은 [개발 지침](development.md), 설치·지원 범위는 [설치 안내](self-hosting.md)를 따른다.

## 이 문서의 사용법

| 접두어 | 범주                | 뜻                                                          |
| ------ | ------------------- | ----------------------------------------------------------- |
| D      | 확정 결정           | 사용자가 명시적으로 확정한 요구                             |
| P      | 제안 이력           | 미승인 제안 또는 표시된 범위만 채택·대체·기각·보류한 제안   |
| O      | 열린 항목·해소 기록 | 사용자 결정 또는 기술 설계; 해소 표시는 해당 기록에 한정    |
| H      | 보류                | 새 승인 없이는 구현하지 않으며 필수 범위의 차단 항목이 아님 |
| X      | 범위 제외           | 이번 범위에서 제외                                          |
| C      | 확인 기록           | 원문 확인 필요 여부와 해소 상태                             |

- `[대체]`·`[기각]`·`[해소]`·`[채택]`은 연결된 범위와 근거에 한정한다. 새 문서·구현이 있다는 이유만으로 결정을 폐기하거나 제안을 채택하지 않는다.
- 근거의 `초안 §n`은 2026-10-17 기획 초안, `지침`은 전달받은 문서, `사용자`는 명시 발언이다. [축약 전 원문과 발언·선택·이력](https://github.com/fvoci/GroundZero/blob/abd545a250ff1fd9cc166b3c078c4dff76846724/docs/decisions.md)을 보존하며 이 색인에서 줄인 것은 새 정책 결정이 아니다.
- 공개·공유·삭제·보존·권한·사용 경험·비용은 사용자 결정이다. 기술 설계는 D-43·D-47에 따라 구현하되 기능 축소·권한 확대·새 서비스/비용은 사용자에게 올린다.
- 구현 해석·coordinator 판단은 사용자 결정과 구분한다. 과거 실행 결과와 미승인 권장안을 현행 요구로 쓰지 않으며 근거 없는 일정 추정은 하지 않는다.

## 0. 이해 요약

한 번 입력한 작업·지식·학습 정보를 여러 화면에서 재사용하는 앱이다. 모듈 인스턴스별 번호, 개인 노트의 소유·공유 경계, 공통 체크리스트, 분석 당시 파일 버전 고정은 아래 결정에 따른다. [이해 확인용 예시](https://github.com/fvoci/GroundZero/blob/abd545a250ff1fd9cc166b3c078c4dff76846724/docs/decisions.md#L31-L51)는 별도 요구가 아니다.

## 1. 확정 결정

### 1.1 제품·기술

<a id="d-01"></a>

- **D-01 신규 개발, 이름 fvoci.** 빈 저장소에서 새로 시작한다. 초안 §2의 기존 FVOCI 확장 여부를 대체한다. 근거: 사용자.

<a id="d-02"></a>

- **D-02 PostgreSQL만 지원.** 초안 §2의 DB 지원 범위 미정을 대체한다. 최소 버전과 환경별 범위는 D-100. 근거: 사용자.

<a id="d-03"></a>

- **D-03 기본 기술 구성.** Rust 백엔드, Rust xtask 개발·빌드·검증, Svelte 프론트엔드, pnpm, Tiptap 블록 편집, CRDT 공동 편집. 근거: 초안 §2·사용자.

<a id="d-04"></a>

- **D-04 검색과 HWP 뷰어.** Meilisearch와 rhwp를 쓴다. rhwp의 형식별 실제 호환성은 별도 검증 대상이다(O-11). 근거: 초안 §2·사용자.

<a id="d-05"></a>

- **D-05 미리보기 범위.** PDF·이미지·텍스트·Office·HWP/HWPX 읽기 미리보기를 포함하고, Office·HWP 본문 편집·수정본 저장은 제외한다(X-01). Office 엔진은 비교 평가 후 선택한다(D-54·D-71·D-74, O-10). 근거: 초안 §17·사용자.

<a id="d-06"></a>

- **D-06 파일 저장과 업로드.** S3 호환 또는 서버 로컬 저장소. 청크 업로드·재개·재시도·무결성 확인, 완료 요청 중복 방지, 취소·만료 잔여 데이터 정리, 다운로드 권한 검사를 제공한다. Cloudflare 경유 시 개별 요청 한도 안에서 전송하며 완료 때 전체 파일을 다시 보내지 않는다. 파일 크기·총 저장량은 운영 설정이다(D-52). 근거: 초안 §2·§17.

<a id="d-07"></a>

- **D-07 셀프호스트 우선, SaaS 고려, 공개 시점.** 셀프호스트를 먼저 완성하고 SaaS를 고려한다. 합의한 전체 기능을 갖춘 뒤 제품을 공개하되, 내부 구현·검증은 작은 사용자 흐름부터 단계적으로 한다. 개발 저장소·CI 이미지의 선공개는 D-65. 근거: 초안 §1·사용자.

<a id="d-08"></a>

- **D-08 SaaS·격리·운영 원칙.** 소유 워크스페이스를 명시하고 공간 간 공유는 명시적 권한으로 처리한다. 관리자는 자기 공간만 열람하며 개인 시간 기록의 비공개를 유지한다. RLS와 앱 권한 검사를 함께 설계하고(O-09), 앱 실행 역할과 운영·마이그레이션 역할을 분리한다. 검색·첨부·캐시·실시간·백그라운드 작업도 격리하며 셀프호스트와 SaaS의 핵심 데이터·권한 의미를 같게 한다. 근거: 초안 §19.

<a id="d-09"></a>

- **D-09 Rust·TypeScript 품질 기준.** Rust는 rustfmt·Clippy를 필수 검사로 쓰고 Clippy 규칙은 선택하며, 고정 툴체인의 경고 오류 처리, 무분별한 unwrap·expect·panic과 오류 버림 금지, 자체 unsafe 기본 금지, 의미 있는 타입·async 책임을 지킨다. TypeScript는 strict·명시 옵션, svelte-check·타입 기반 ESLint, unknown에서 외부 입력 검증, any·이중 단언·@ts-ignore 금지, 비동기 오류·취소·오래된 응답 처리·수명주기 해제를 지킨다. Rust↔TS 계약·전송 표현·상태 정본을 단일화하고 런타임 검증을 유지한다. 세부·예외·복잡도 원칙과 이미 구현한 검사 설정은 [개발 지침](development.md)과 O-22·O-23. 근거: 품질 기준 지침.

<a id="d-10"></a>

- **D-10 Docker Compose 개발·통합 테스트 환경.** PostgreSQL·Meilisearch·테스트 S3 저장소·격리된 Keycloak(D-45)을 컨테이너로 실행한다. 운영·개인 개발 DB로 시험하지 않는다. 버전·이미지·명령을 로컬과 CI에서 맞추고, 빌드/실행 이미지 분리·병렬 실행 격리·UID/GID 검증·시크릿 분리·자원별 동시 실행 제한·자기 자원만 정리를 지킨다. privileged·Docker 소켓·호스트 전체 마운트를 금지한다. 호스트 도구 허용 범위와 구현된 xtask·pnpm 명령은 [개발 지침](development.md). 근거: Compose 지침.

### 1.2 제품 목적과 구현 원칙

<a id="d-11"></a>

- **D-11 제품 목적.** 프로젝트·연구·스터디·강의·취미의 업무·문서·일정·자료·시간을 한곳에서 관리하고 연결한다. 중복 입력을 줄이며 한눈에 보고 빠르게 찾게 한다. 개인·소규모 팀 모두 지원하고 혼자 쓸 때 불필요한 협업 절차를 강제하지 않는다. Plane·Kaneo·Outline의 유용한 경험을 참고한다. 근거: 초안 §1.

<a id="d-12"></a>

- **D-12 구현 원칙.** 같은 정보·상태는 한 정본으로 여러 화면에서 재사용하고 모듈마다 공통 기능을 재구현하지 않는다. UI 표시와 저장 성공, 읽기와 수정·복제·다운로드 권한을 구분한다. 실패·재시도·동시 편집·권한 철회·복구도 검증한다. 사용자에게 Markdown·내부 ID 이해를 요구하지 않는다. 공개 범위는 합의 목록이며 추가 아이디어는 후속이다(X-08). 근거: 초안 §20.

### 1.3 구조·명칭

<a id="d-13"></a>

- **D-13 워크스페이스.** 사람·권한·콘텐츠를 묶는 공간이며 한 사용자가 여러 공간에 속할 수 있다. 홈·위키·프로젝트/연구/스터디/강의/취미 모듈·검색·내 업무·최근 항목·즐겨찾기·알림을 둔다. 근거: 초안 §3.

<a id="d-14"></a>

- **D-14 용어.** 위키는 공간 공용 지식, 문서는 위키·모듈 콘텐츠, 모듈은 다섯 기능 유형, 항목은 개별 프로젝트·연구·스터디·강좌·취미 활동이다. 목록은 항목 탐색, 보기는 목록·칸반·달력 등의 표현, 워크플로는 업무 상태·전환이다. 모듈 안은 ‘프로젝트 위키’ 대신 ‘프로젝트 문서’ 등으로 부른다. 근거: 초안 §3·사용자.

<a id="d-15"></a>

- **D-15 다섯 유형과 모듈 복수 생성.** 프로젝트·연구·스터디·강의·취미를 제공하고 같은 유형도 DEV·OPS처럼 여러 모듈을 만들 수 있다. 초안 §21의 미정을 대체한다. 근거: 사용자.

<a id="d-16"></a>

- **D-16 모듈 이름.** 표시 이름은 사용자가 정하고 이름을 바꿔도 내부 기능 유형은 유지한다. 근거: 초안 §4.

<a id="d-17"></a>

- **D-17 ID·배지·번호.** 워크스페이스 내부 ID는 UUIDv7이며 표시 이름 중복을 허용한다. 같은 이름은 색상 배지·아이콘·보조 정보로 구분하고 색상은 자동 지정 또는 사용자 선택이다. 권한·참조는 내부 ID를 쓰며 각 항목의 내부 ID는 불변이다. 사람용 번호는 공간·모듈 인스턴스 범위에서 원자적으로 증가한다(D-48). 삭제 번호 재사용·정렬/이름 변경에 따른 재매김·재시도 중복 생성을 금지하고 빈 번호는 허용한다. 근거: 초안 §4·사용자.

<a id="d-18"></a>

- **D-18 @ 링크와 사용자 언급.** 위키 참조 키는 WIKI, 모듈은 이름과 짧은 키를 분리한다(`@A/DEV-1`, `@영환`). 사람·항목·문서·업무를 구분해 찾고 선택 대상은 내부 ID, 표시는 배지·번호·제목을 쓴다. 같은 공간에서 대소문자를 무시해 키 중복을 막고 WIKI를 예약한다. 이름·키 변경 뒤 연결을 유지하며 옛 키는 재사용할 수 없는 별칭으로 남긴다. 동명 후보는 사용자가 고른다. 언급은 담당 지정·권한 부여가 아니며 링크·역방향 링크·멘션 알림에 원본 접근권한을 적용한다. 항목과 그 안의 문서는 별도 대상이다(D-48). 근거: 초안 §5·사용자.

### 1.4 워크스페이스 홈

<a id="d-19"></a>

- **D-19 홈 구성.** 오늘·빠른 업무/메모/일정 추가·실행 타이머·주간 달력/가까운 일정·기한 초과/오늘/다가오는 업무 중심 Up Next·수동 고정·진행 중 다섯 유형 항목·최근 문서/작업·즐겨찾기·협업 활동/알림을 둔다. 업무 완료율·강의 이수율·공부 목표 등 서로 다른 진행률을 같은 의미로 합산하지 않는다. 근거: 초안 §6.

### 1.5 멤버·권한·공유

<a id="d-20"></a>

- **D-20 역할과 기본 권한.** 관리자·작성자·독자, 초대·제거·역할 변경·그룹 관리를 제공한다. 새 항목은 기본 비공개이며 공간 공개를 선택할 수 있다. 독자는 읽기·댓글이 가능하다. 재공유는 소유자·공유 관리 권한자만, 복제·다운로드 허용은 소유자가 별도로 정한다. 상위 공유를 기본 상속하되 문서 비공개 예외를 허용한다. 비로그인 공개 링크는 명시적 활성화·만료·철회를 지원한다. 근거: 초안 §7.

<a id="d-21"></a>

- **D-21 관리자 열람.** 관리자는 해당 공간의 모든 문서를 열람하며 그 범위를 사용자에게 명확히 알린다. 비공개 예외는 D-40, 감사로그는 D-57. 근거: 초안 §7·선택 2번·사용자.

<a id="d-22"></a>

- **D-22 개인 노트.** 공간 관리자에게도 비공개인 개인 노트를 제공한다. 서버·DB 운영자에게 비밀을 보장하는 암호화는 확정 요구가 아니다(H-01). 소유·공유는 D-49·D-59로 초안 §21의 미정을 대체한다. 근거: 사용자.

<a id="d-23"></a>

- **D-23 원본 공유와 복제.** 소유자는 특정 사람에게 읽기·수정 권한을 줄 수 있고 공유받은 사람의 수정은 원본에 반영된다. 복제는 독립 사본이며 이후 자동 동기화하지 않는다. 근거: 초안 §7·사용자.

<a id="d-24"></a>

- **D-24 워크스페이스 간 참조·공유·이동.** 모두 포함하고 이동 전에 공개 범위·권한 변화를 확인한다. RLS 복잡성을 이유로 제외하거나 미정으로 되돌리지 않는다(P-R01 기각). 근거: 초안 §7·사용자.

<a id="d-25"></a>

- **D-25 탈퇴와 소유권.** 팀 공간에서 만든 문서는 작성자 탈퇴 뒤에도 남고 관리자가 인계한다. 공유한 개인 원본은 별도 소유권을 유지한다. 근거: 초안 §7.

<a id="d-26"></a>

- **D-26 보호 범위의 한계 안내.** 복제·다운로드 제한이 화면 촬영까지 막는다고 설명하지 않는다. 근거: 초안 §7.

### 1.6 문서 편집·리비전·감사로그

<a id="d-27"></a>

- **D-27 문서 편집 경험.** Tiptap 노션형 블록/리치 편집을 기본으로 Markdown 원본 편집(추가 입력 방식)·읽기 미리보기·문서 트리/템플릿·표/코드/수식/이미지/첨부·댓글/멘션/공동 노트·링크/역방향 링크·자동 저장/상태 안내·미저장 초안 보호·리비전/diff/복원을 제공한다. 모드 전환에 내용을 잃지 않고 Markdown 지식을 필수로 하지 않는다. 공동 편집은 공간별 선택이며 OFF에서도 충돌과 차이를 확인해 반영한다. 위키·모듈 문서 모두 리비전/diff/복원 대상이고 업로드 파일 내부 diff 제외(X-03)와 구분한다. 근거: 초안 §8·사용자.

<a id="d-28"></a>

- **D-28 감사로그.** 생성·삭제·이름 변경 등의 감사로그를 포함한다. 이벤트·열람·보존은 D-57. 근거: 사용자.

<a id="d-29"></a>

- **D-29 복원 규칙 설계.** 문서 복원과 연결 업무·수강 진도 상태 변경을 구분한다(D-58). 근거: 사용자.

### 1.7 체크리스트

<a id="d-30"></a>

- **D-30 체크리스트 공통 입력.** 편집기가 없어도 체크박스·내용 입력으로 추가/수정/삭제/완료 변경을 제공한다. 편집기 본문과 별도 폼에서 같은 목록을 보여주면 동일 항목·상태를 참조하고 중복 저장하지 않는다. 붙여넣은 Markdown의 완료 상태·내용을 일반 입력 영역으로 가져와 사용자가 확인·수정한다. 모든 목록을 문서 본문이나 업무로 강제하지 않고, 일반 체크가 업무 생성·강의 완료를 자동 수행하지 않는다. 업무 전환·기존 업무/회차 연결은 제안(P-10), 저장/연결/재가져오기 설계는 O-04다. 근거: 초안 §9·사용자.

### 1.8 공통 업무·일정

<a id="d-31"></a>

- **D-31 업무·일정.** 업무·한 단계 하위 업무, 상태·우선순위·복수 담당자·시작/마감일·태그·체크리스트·예상 시간·마일스톤·선후행 관계·반복 업무, 회의/발표/행사 일정, 목록/칸반/달력/간트·검색/필터/정렬/저장 보기를 제공한다. 업무 완료는 담당자 간 공유하고 강의 이수는 개인별이다. 선행 일정 변경은 영향·충돌을 보여 후속 재배치를 승인받는다. 미완료 반복 업무를 남기고 다음 회차는 원래 일정대로 만든다. 근거: 초안 §10·사용자.

### 1.9 공통 스톱워치·시간 기록

<a id="d-32"></a>

- **D-32 시간 기록.** 모든 모듈에서 시작/일시정지/재개/종료, 업무·문서·공부·강의 회차·취미 연결, 측정 후 분류, 수동 입력/수정/이력/메모, 일·주·월 집계와 예상/실제 비교를 제공한다. 사용자당 모든 공간에서 실행 타이머 하나, 앱 종료 뒤 측정 지속·재접속 복구다. 기본 비공개이며 선택한 집계만 공유한다. 순공부시간은 강의 시청을 제외한 능동적 공부다. 실제 인강 수강·휴식·영상 원본 길이·배속 기준 예상 시간을 구분한다. 근거: 초안 §11·사용자.

<a id="d-34"></a>

- **D-34 연구 모듈.** 이름·분야·키워드·책임자·공동 연구자·질문·가설·모형·방법·표본·기간·상태를 관리한다. 문헌은 저자/연도/학술지/DOI/URL/PDF·읽기 상태/태그/요약/인용/페이지 연결, 개인/공동 노트·선행연구 비교·계획서·개념/변수/측정/용어집·실험/인터뷰/랩미팅/피드백/결정/설계 변경 기록을 포함한다. 자료는 파일/외부 위치/출처/수집일/버전·변수 사전/코드북·원자료/정제/분석 자료 구분·결측/제외/품질/권한, 분석은 목적/담당/상태/입력 자료와 코드의 버전/설정/로그/오류/실행 시각/표/그림/재실행 비교를 관리하고 이전 버전·분석 당시 연결을 보존한다. 코드는 외부에서 실행하고 앱은 파일·로그·결과·연결을 관리하며 사람 작업과 컴퓨터 실행 시간을 구분한다. 연구 업무·칸반/달력/간트/마일스톤, 논문/투고 대상/학회·제출/수정 마감·공동저자 검토/제출 체크리스트·제출본/심사의견/답변서·투고/심사/수정/게재 상태, 필요 시 IRB 자료·일정을 제공한다. Zotero는 서지 정보·컬렉션 읽기·원본 링크만 지원한다(X-02·X-03·X-05). 근거: 초안 §13.

<a id="d-38"></a>

### 1.11 검색·알림·가져오기·복구

<a id="d-39"></a>

- **D-39 검색·알림·가져오기·복구.** Meilisearch로 문서·업무·항목·자료와 지원 형식 첨부 본문을 검색하고 모듈·담당자·상태·날짜로 거른다. 멘션/댓글/기한/일정/협업 알림, 파일 첨부·CSV 업무/강좌 등록·Markdown 체크리스트 가져오기, 휴지통/복원/버전 보존·반출/백업/DB와 첨부의 일관된 복구를 제공한다. 전체 Markdown·Notion 문서 가져오기는 제외한다(X-04). 검색 결과·요약·역방향 링크·알림은 접근권한을 따르며 철회된 내용이 오래된 색인·캐시로 노출되지 않게 한다. 근거: 초안 §18.

### 1.12 이후 추가된 결정

<a id="d-40"></a>

- **D-40 관리자 열람과 문서별 비공개의 관계.** 관리자는 자기 공간의 비공개 문서도 열람한다. D-20의 비공개 예외는 일반 멤버에 적용되고 개인 노트는 별도 영역·권한이다(D-22). O-21 해소. 근거: 사용자.

<a id="d-41"></a>

- **D-41 휴지통 보존 기간.** 기본 30일이며 관리자가 설정할 수 있다. 최초 기록에서 누락됐던 선택 9번을 보완했다. 근거: 선택 9번·사용자.

<a id="d-42"></a>

- **D-42 품질 검사 검증 기록 방식.** 검사 설정을 구현하고 대표 위반을 실제로 잡는지 확인한다. 명령·대상 SHA·결과·필요한 실패 로그를 PR이나 작업 보고에 남기며 별도 증거 프레임워크는 만들지 않는다. O-24 해소. 근거: 사용자.

<a id="d-43"></a>

- **D-43 열린 항목의 처리 방식.** 사용자 결정과 기술 설계를 구분한다. 기술 설계는 검토자가 근거·권장안·대안을 제시하고 구현 시 진행한다. 기능 축소·권한 확대·새 서비스·비용은 사용자 결정으로 남긴다. 근거: 사용자.

<a id="d-45"></a>

- **D-45 인증 방식: OIDC 전용.** Keycloak을 기준 제공자로 검증하되 전용 API에 불필요하게 의존하지 않는다. 로그인·자격 증명·비밀번호 복구·MFA는 제공자, 앱 세션·프로필·초대·멤버십·역할·문서 권한은 fvoci가 담당한다. 로그인만으로 모든 공간 권한을 주지 않고 issuer+subject로 식별하며 같은 이메일로 자동 병합하지 않는다. 격리된 Keycloak으로 로그인/만료/로그아웃/권한 거부를 시험한다. 초기 관리자·초대는 D-51, 선택적 Keycloak 배포는 O-25, 자체 비밀번호 인증·SAML은 제외한다(X-09). O-13 해소. 근거: 인증 지침.

<a id="d-46"></a>

- **D-46 저장소 초기 구조 기준.** [저장소 구조](repo-structure.md)를 초기 기준으로 승인했다. 빈 폴더·파일을 미리 모두 만들지 않고 필요할 때 만든다. 개발 지침은 `development.md`로 통일해 옛 파일을 중복 유지하지 않는다. 당시 승인은 구조·문서 정리에 한정했고 제품 구현 착수와 구분했다. C-02 해소. 근거: 사용자(2026-10-17).

<a id="d-47"></a>

- **D-47 사용자 결정과 구현 선택의 경계.** 기능 범위·권한·삭제/보존·비용·외부 서비스는 사용자 결정이다. 파일명·배치·lint·검증 기록 방식은 승인된 원칙 안에서 검토자가 정하고 이유를 간단히 남긴다. 모든 구현 선택을 승인 대기로 만들지 않는다(D-43 구체화). 근거: 사용자.

<a id="d-48"></a>

- **D-48 번호 체계.** 모듈 인스턴스마다 항목·업무·문서가 한 번호열을 공유한다. 유형과 무관하게 번호가 중복되지 않으며 화면에서는 유형 아이콘·제목으로 구분한다. O-01 해소, P-03 채택. 근거: 사용자.

<a id="d-49"></a>

- **D-49 개인 노트 공유.** 기본 비공개이며 소유자가 특정 사람에게 읽기·수정 권한을 줄 수 있다. 공유해도 개인 소유를 유지하고 상대 공간의 관리자에게 권한이 따라가지 않는다(D-23). O-02 해소, P-04 기각. 근거: 사용자.

<a id="d-50"></a>

<a id="d-77"></a>

- **D-77 ETag·조건부 요청·캐시 범위.** CDN 없는 셀프호스트와 Cloudflare·CloudFront 앞에서 권한·저장 정합성을 같게 유지한다. 캐시 정책은 앱이 정하고 CDN 설정은 예시다. 근거: 사용자.
  - 문서 단건 GET(위키·모듈·개인 노트)의 강한 ETag는 실제 응답 바이트·요청 사용자의 해시다. 세션·권한 확인 뒤 `If-None-Match`를 약한 비교해 같으면 304, 권한 철회는 404·로그아웃은 401이다.
  - PUT의 선택적 `If-Match`는 같은 트랜잭션·문서 행 잠금에서 요청 id 재시도 판단 다음, `base_revision` 비교 전에 현재 표현과 강한 비교한다. 불일치는 412+최신본(409와 같은 모양)이며 초안을 보존한다. 약한 ETag는 일치로 보지 않는다. 헤더가 없으면 기존 `base_revision`의 409를 쓰고 CRDT·저장 확인·멱등 키 역할을 바꾸지 않는다.
  - API 응답을 압축하지 않고 `no-transform`을 붙인다. 클라이언트는 강한 ETag일 때만 `If-Match`, 약해졌으면 `base_revision`만 쓴다.
  - 해시 정적 자원(`/assets/*`, `/rhwp/<해시>/*`)은 `public, max-age=31536000, immutable`. HTML·SPA·해시 없는 자원·rhwp manifest는 `no-cache`. `/api`·`/auth`·`/healthz` 중 문서 단건 GET만 `private, no-cache, no-transform`이고 나머지(인증·개인 데이터·첨부·내보내기·익명 링크 포함)는 `no-store`다. 없는 해시 자원은 SPA가 아닌 404, 압축 정적 응답은 `Vary: Accept-Encoding`이다.
  - Cloudflare 민감 경로 Cache Bypass는 다른 규칙보다 뒤에 두고 API의 Respect Strong ETags를 켜며 브라우저 TTL은 원본을 존중한다. CloudFront 민감 경로는 CachingDisabled+AllViewer로 쿠키·Authorization·Origin·조건부 헤더를 전달한다. 해시 자원만 캐시·압축(CloudFront CachingOptimized)하며 사용자별 캐시 키로 격리를 대신하지 않는다. 로그인/로그아웃/콜백/쓰기의 메서드·Set-Cookie·If-Match·304/412·웹소켓을 원본에 그대로 전달하고 캐시하지 않는다.
  - 객체 저장소 ETag·API ETag·SHA-256 무결성 체크섬을 구분한다. 비공개 첨부는 앱을 거치고 영구 공개 URL로 바꾸지 않는다. 업로드 조각 5~64 MiB는 프록시 요청 한도 안이고 완료 시 파일 전체를 재전송하지 않는다. 새 캐시 서버·범용 틀은 만들지 않는다. 실제 클라우드 설정·유료 서비스는 별도 승인, 승인된 대상의 실제 CDN 검증 전에는 NOT RUN이다.

<a id="d-78"></a>

- **D-78 모듈별 기능 대조와 공통 구현 원칙.** 새로운 범위를 늘리지 않고 D-31~D-38과 기존 구현을 재사용한다. 2026-10-17의 구현/검증 상태표는 개발 지침 63절의 역사 기록이다. 근거: 사용자.
  - 모든 모듈은 업무·문서/리비전·체크리스트(업무 행/문서 본문 노드)·첨부/버전·시간 기록(일/공부/강의/휴식/기타 및 아래 취미)·일정·권한·알림·감사 정본을 공유한다. 칸반/목록/달력/간트는 같은 업무 목록을 보고 다시 읽은 변경을 함께 반영한다.
  - 모듈 전용 정본은 강좌/회차/개인 진도, 스터디 계획 단위/개인 진행, 항목 기록(연구 문헌/데이터/변수/분석/투고, 프로젝트 산출물/위험/문제/회고, 스터디 자료/모임/시험/복습, 취미 재료/장비/사용/활동/결과물)이다.
  - 업무 완료는 공유, 강의·스터디 진행은 개인별이다. 진행 행은 본인만 읽고 함께 보기에는 집계만 쓴다. 재수강은 시간만 늘리고 완료 수는 유지한다.
  - 모듈(키/이름/아이콘)→항목(제목/설명/정보/리더/멤버/공개)→업무/문서/일정/첨부/기록/전용 패널→보관/휴지통/복구 흐름을 제공한다. 칸반·달력·표시는 D-79~D-81이다. 항목별 시간은 같은 기록의 업무/회차/스터디 단위/항목 대상을 종류별로 모으며 본인 기록과 공유를 켠 사람의 집계만 보여준다.
  - 사용자 선택: 관리자용 모듈 설명, 모듈 휴지통·관리자만 복구, 시간 종류 ‘취미’를 추가한다. 모듈 행만 휴지통에 넣고 복구하며 앞서 따로 지운 항목은 자기 묶음에 남긴다. 항목 공개·멤버를 바꿔 권한을 넓히지 않는다.

<a id="d-79"></a>

- **D-79 칸반 끌어서 놓기.** 화살표·Alt+방향키를 유지하면서 마우스·터치를 추가하고 열/위치 변경은 하나의 이동 API를 쓴다. 마우스는 6px 이상 움직여야 끌기, 클릭은 열기다. 터치·펜은 손잡이에서만 끌고 카드는 스크롤한다. 낙관적 반영 뒤 실패하면 되돌리고 동시 변경(400)·권한 철회(403)·삭제(404)·보관(409)·네트워크 실패를 알린 뒤 최신 목록·항목을 읽는다. 조건부 이동 충돌은 D-89다. 비기본 정렬에서는 열만 바꾸고 사용자 정의 열·자동화는 추가하지 않는다. 근거: 사용자.

<a id="d-80"></a>

- **D-80 달력 범위와 날짜 출처.** 하나의 달력 조회를 공간→모듈→항목 범위로 사용하고 공간 화면에는 모듈·항목 필터를 둔다. 모듈별 일정 사본은 만들지 않는다. 정본 출처는 일정/반복 회차, 업무 시작·마감/향후 반복 업무, 강의 수강 예정일, 스터디 계획일, 연구 제출/수정 마감, 프로젝트 산출물 마감, 취미 연습 일정이다. 강의·스터디는 본인의 개인 계획일 우선, 없으면 공통일을 쓰고 출처를 표시한다. 개인 계획은 본인만, 모든 출처는 항목 접근권한 안에서 보여준다. 개인 시간 기록은 달력에 넣지 않는다. 근거: 사용자.

<a id="d-81"></a>

- **D-81 표시 언어와 날짜·시간 정책.** 근거: 사용자.
  - 한국어(원본)·영어로 메뉴/폼/오류/알림/달력/접근성/내보내기를 번역한다. 사용자 내용은 번역하지 않는다. Paraglide JS 2와 언어별 메시지 파일 하나를 쓰며 변수 치환·복수형을 사용하고 키 누락/불일치는 check가 거부한다. 서버 오류·감사·상태 값은 언어 중립이며 번역문을 DB 상태로 쓰지 않는다.
  - 언어·IANA 시간대·주 시작(월/일)·12/24시간을 따로 골라 계정에 보존한다. 저장값이 우선이고 없을 때만 브라우저 언어/시간대를 제안한다. 주 시작·시각 형식 기본값은 선택 언어 관례다. 브라우저 변경으로 저장값을 덮지 않고 표시 설정으로 일정 시각/날짜를 바꾸지 않는다.
  - 실제 시각은 UTC 저장·전송/사용자 시간대 표시, 날짜 전용 값은 날짜다. 반복 일정은 자체 시간대·현지 시각을 유지한다. 없는 현지 시각의 반복 회차는 건너뛰고 그 사실을 표시하며 겹친 시각은 앞선 한 번만 만든다(RFC 5545 §3.3.10). 단건 생성은 없는 시각을 거부해 다시 고르게 하고 겹친 시각은 앞선 것으로 읽는다. 기존 일정·시간의 편집은 D-93이다.
  - 시간 원본은 나누지 않고 일/주/월 합계만 사용자 시간대 자정으로 나눈다. 일시정지 시각을 저장하지 않으므로 일시정지 시간은 경과 비율로 빼고 나눈 합을 원래 합과 같게 한다. 주 합계는 사용자 주 시작, 타이머 경과는 표시 설정과 무관하다.
  - 모든 날짜 화면(달력/날짜 선택/간트/홈/강의/스터디/시간 기록)은 같은 설정으로 오늘·주·월 경계를 계산한다. 일요일 고정·서버 지역 시간에 기대지 않는다. 공동 일정의 원래 시간대가 다르면 함께 표시하고 `Intl` 위의 작은 공통 포매터를 쓴다.

<a id="d-82"></a>

- **D-82 사용자 피드백 규칙.** 일반 완료는 오른쪽 아래 토스트(모바일 탐색·키보드와 겹치지 않게), 입력 오류는 필드 옆, 저장 실패·충돌은 입력/재시도를 보존한 화면 내 메시지, 연결은 배너, 멘션·초대는 알림함이다. 자동 저장 성공은 편집기 상태에만 표시한다. 반복 오류 토스트는 쌓지 않고 갱신한다. 토스트·배너는 aria-live로 알리며 키보드로 닿고 닫혀야 한다. 기존 UI·i18n을 쓴다. 근거: 사용자.

<a id="d-83"></a>

- **D-83 운영 로그 레벨과 JSON Lines.** 기존 tracing을 쓰고 새 로그 프레임워크·서비스는 두지 않는다. 근거: 사용자.
  - 기본 INFO, `FVOCI_LOG`로 ERROR~TRACE·모듈별 필터를 시작 때 읽으며 잘못된 설정은 시작을 거부한다. 옛 `RUST_LOG` 별칭은 D-92로 제거했다. ERROR는 처리 실패/정합성, WARN은 복구 가능한 이상(외부 502 포함), INFO는 시작/종료/주요 결과/요청 접근(거절이면 error_code 포함), DEBUG·TRACE는 진단이다. 4xx는 오류 줄 대신 접근 status_code, healthz·정적 접근은 DEBUG다.
  - stdout JSON Lines(`FVOCI_LOG_FORMAT=json`)의 필드는 timestamp(UTC RFC3339)·level·target·안정된 event·message와 해당하는 request_id/job/job_id/status_code/duration_ms(밀리초 숫자)/error_code(응답 오류 코드와 같은 값)/detail이다. 색·원시 줄바꿈은 없고 로그는 UI 언어와 무관하다. 개발 pretty도 같은 사건·필드의 한 줄이다.
  - 안전한 x-request-id 또는 새 UUIDv7을 응답 헤더·오류 본문·로그에 같이 쓴다(권한 근거 아님). 주기 작업은 실행별 ID, 화면의 5xx는 안전한 문구·요청 ID만 표시한다. 서버 오류는 응답 변환 경계에서 한 번 기록한다.
  - 어떤 레벨에도 비밀번호/토큰/쿠키/Authorization/OIDC 코드/서명 URL/문서·첨부 내용/요청·응답 본문·헤더·쿼리/설정값/DB 바인딩/외부 오류 원문을 쓰지 않는다. 실제 경로 대신 경로 틀, 오류는 자체 분류·SQLSTATE·제약 이름만 남긴다. HTTP/TLS/웹소켓/OIDC/DB 라이브러리는 info 상한, pdf_extract·lopdf 로그와 SQL 문장/느린 질의 로그는 끈다. 작업 함수 경고도 SQLSTATE만, 패닉도 위치만 한 줄이다.
  - DB audit_log는 로그 레벨과 별개다. 보관은 Docker json-file 회전(기본 10 MB×5, `FVOCI_LOG_MAX_SIZE`·`FVOCI_LOG_MAX_FILE`)이며 앱 내 파일 로그/회전기·로그 서버·실시간 로그 UI·외부 전송은 제외한다. 운영 절차는 [설치 안내](self-hosting.md).

- **D-86 Noto Sans KR·Noto Serif KR·D2Coding 서체.** Noto Sans KR 2.004·Noto Serif KR 2.003·D2Coding 1.4.0의 Regular/Bold 여섯 파일에만 OFL-1.1 예외를 허용한다. 다른 파일·라이선스 전체 허용이 아니다. 외부 CDN·글자별 조각 요청은 금지한다. 근거: 사용자(2026-10-18), O-37 해소.

<a id="d-87"></a>

- **D-87 제품 이미지 릴리스와 버전 표시.** 검증한 원격 `vX.Y.Z` 태그(main에 포함된 커밋)의 제품 이미지를 Actions에서 GHCR `ghcr.io/fvoci/groundzero:X.Y.Z`로 게시한다. CI 베이스 이미지와 구분하고 latest는 없다. D-65 중 제품 이미지 게시만 추가 승인했으며 main 병합·태그 생성/이동·SaaS 배포는 별도다. 근거: 사용자(2026-10-20).
  - 버전은 X.Y.Z, 소스는 전체 태그 SHA이며 CI가 한 번 정해 빌드 인자·OCI 라벨·확인값에 같이 쓴다. Cargo 0.1.0은 제품 버전이 아니다. 서버 healthz의 build/시작 로그/version 명령과 계정 메뉴에 같은 값을 낸다. 미주입 빌드는 dev, 한 값만 있거나 형식 오류면 컴파일 실패다.
  - 주입 전 v0.0.1만 태그를 옮기지 않고 예외 빌드한다(라벨에만 버전/SHA, 앱에는 없음). 다른 주입 전 태그는 거부한다.
  - 무료 GitHub-hosted 네이티브 amd64·arm64에서 각각 빌드/확인한 뒤 게시한다. 같은 이미지 태그는 SHA가 같을 때만 유지하고 다르면 실패한다. 게시 job만 기존 GITHUB_TOKEN의 게시 권한을 가지며 PR은 게시하지 않는다.

<a id="d-88"></a>

- **D-88 셀프호스트 Supabase를 DB 배포 대상으로.** 기존 자체 PostgreSQL 지원·기본 설정과 Rust 서버·Keycloak/OIDC·S3/R2/local·Meilisearch·작업 대기열을 유지한다. Supabase Auth/Storage/Realtime/Data API·화면의 직접 DB 접근을 추가하지 않는다. 당시 Cloud 제외는 D-100의 공통 구현 설계·검증 대상으로 대체됐다(원격 변경 승인 아님). 근거: 사용자(2026-10-20).
  - 관리자는 superuser일 필요가 없다. bootstrap은 **변경 전에** 기존 두 역할의 SUPERUSER/CREATEROLE/BYPASSRLS, 앱 역할의 CREATEDB도 금지하고 관리자 ADMIN OPTION(간접 포함)을 확인한다. 문제 시 무변경 종료, 정상일 때 속성은 유지하고 비밀번호만 갱신한다. 역할·멤버십·스키마 변경은 한 트랜잭션이다.
  - 관리자는 두 역할을 만들었거나 ADMIN OPTION이 있어야 한다. 소유자로 할 작업은 상속 없는 SET 멤버십을 잠시 받아 원복한다. 기존 멤버십은 삭제하지 않고 옵션만 되돌리며 복구 연결이 끊기면 새 관리자 연결로 한 번 더 원복한다. 복구 관리자 권한은 session_replication_role 설정에만 쓴다. 그 능력은 superuser, Supabase supautils 허용 또는 일반 PostgreSQL에서 superuser의 GRANT SET ON PARAMETER로 준비한다.
  - 새 행 UUIDv7은 Rust Uuid::now_v7()이 만든다. DB id 기본값·UUID 생성 함수/트리거는 두지 않는다. 생성 함수는 마지막 p_ids에서 차례로 소비하고 부족 FV001은 HTTP 409/작업 트랜잭션 전체 재시도, 잘못된 ID FV002는 500이며 대체 생성하지 않는다. 가변 행 수는 같은 트랜잭션의 <함수>_ids가 상한(권한 없으면 0)을 주고 표는 uuid_extract_version(id)=7을 검사한다. PG17에 uuidv7()를 따로 만들지 않는다.
  - 문서 제목 감사는 제목을 바꾸는 두 경로가 app_audit_document_rename으로 남기고 리비전의 전후 제목을 읽어 리비전당 한 번 기록한다. 개발 SQL도 xtask가 넘기는 ID를 쓴다. 상세 호출·재시도는 [UUID 계약](sql-id-contract.md).
  - 사용자 지시로 기존 마이그레이션의 id 기본값을 고쳤다. 당시 개발 DB는 checksum 불일치로 재생성이 필요하지만 삭제는 사용자 확인 뒤다.
  - 소유자는 fvoci_migrator, 앱은 fvoci_app NOBYPASSRLS, RLS는 트랜잭션 app.user_id를 쓴다. auth.uid()로 바꾸거나 fvoci 스키마를 Data API에 노출하거나 anon/authenticated에 권한을 주지 않는다.
  - Supabase CI job만 D-64 이미지 계약의 예외다. xtask가 호스트 Docker로 공식 구성을 띄우고 실패 후 정리 전에 상태/로그를 읽기 위해 호스트 러너에서 실행한다. 툴체인은 같은 고정 판이며 다른 job 계약은 유지한다.

<a id="d-89"></a>

- **D-89 칸반 이동의 조건부 저장.** 업무별 move_version을 두고 열·위치가 바뀔 때 어느 함수에서든 트리거로 증가시킨다. 필드 version과 분리하며 열 재매김도 이동 판을 올린다. base_move_version이 있으면 행을 잠근 같은 트랜잭션에서 비교해 다를 때 무변경 409 move_conflict+현재 업무를 준다. 재시도·되돌리기는 조건 필수, 409 뒤 자동 재전송 없이 최신 상태를 보여준다. 최초 이동은 무조건 이동(D-79)을 유지한다. 옛 호출 호환 의무만 D-92가 대체했다. 근거: 사용자(2026-10-21).

<a id="d-90"></a>

- **D-90 간트의 주 머리글.** 월·주·날짜 세 줄과 D-81의 사용자 주 시작을 쓴다. 월요일은 ISO 주차/주차 연도(그 주 목요일 연도)+실제 날짜 범위, 일요일은 날짜 범위만 쓰고 낭독기에도 주차 없음으로 알린다. 좁으면 줄이거나 비우고 전체 설명은 낭독기/title에 둔다. ‘10월 1주’나 주차 숫자만 쓰지 않는다. 부분 주는 보이는 열만 차지하며 UTC 자정 일수로 계산해 표시만 바꾼다. 기본 주 시작은 선택 언어 관례다. 근거: 사용자(2026-10-21).

<a id="d-91"></a>

- **D-91 선행 관계의 종류와 지연일.** FS·SS·FF·SF와 0~3650 정수 달력 일 지연을 지원한다. 음수 lead·근무일 달력·시간 단위는 제외한다. 업무 쌍당 한 관계이며 기본값은 FS·0, 후속 목록도 같은 정본을 역조회한다. 근거: 사용자(2026-10-21).
  - 날짜는 하루 전체이며 시작=시작일??마감일, 끝=마감일??시작일이다. A→B의 제약은 FS: B시작≥A끝+1+지연, SS: B시작≥A시작+지연, FF: B끝≥A끝+지연, SF: B끝≥A시작−1+지연이다.
  - 미리보기→명시 승인→저장(D-31). 새로 움직인 선행·고친 관계가 전보다 더 요구하는 만큼만, 여러 관계 중 최대 요구로 뒤로 민다. 기간을 유지하고 이미 충족한 업무는 그대로이며 앞당기지 않는다. 날짜 없음·완료 업무는 옮기거나 그 뒤로 전파하지 않는다. 날짜 없음은 알리고 지어내지 않는다. 각 업무의 전후 날짜·원인 관계를 보여준다.
  - 관계 변경은 업무 version을 올리지 않고 move_version은 열·위치만 보호한다. 서버는 저장 트랜잭션에서 관계·업무를 잠근 뒤 재계산해 승인한 업무·날짜가 하나라도 다르면 무변경 409 shift_conflict를 준다. 승인 목록이 빈 저장(옮기지 않기로 함)은 비교하지 않는다. 관계 변경과 승인한 재배치는 한 트랜잭션이다.
  - D-92 후 현재 계약은 predecessors(업무/종류/지연) 응답, schedule-plan 미리보기, 필수 관계 수정 본문+편집 시작 관계 base다. 관계가 바뀌었으면 409 link_conflict다. 옛 predecessor_ids 응답·schedule-preview·본문 없는 PUT은 제거했다. 항목 복제는 종류·지연도 복사한다.
  - 간트 선은 관계별 끝을 잇고 화살표는 선행→후속이다. 선 이름·초점·가리킴 설명을 함께 쓰며 색만으로 구분하지 않는다. 끌어서 관계 만들기는 제외한다.

<a id="d-92"></a>

- **D-92 최초 정식 릴리스 전의 하위호환 정책.** 과거 개발 버전의 하위호환을 보장하지 않고 그 호환만을 위한 불필요한 코드를 유지하지 않는다. 근거: 사용자(2026-10-21).
  - 경계는 정식 `v1.0.0` 태그의 **원격 push**다. 로컬 태그 생성·배포 완료가 아니며 원격 게시 뒤 상세 호환 정책은 별도 결정한다. D-87의 태그 불변성·별도 승인 규칙은 유지하며 SaaS 자동 배포를 뜻하지 않는다.
  - 확정된 새 설계가 대체한 API·설정·SQL·자료구조의 호환 분기/별칭/fallback은 제거한다. 대체 근거와 현재 호출자·흐름·기존 데이터 영향을 먼저 확인하고 코드·시험·문서·seed를 함께 갱신하며 명령/SHA/결과를 남긴다(D-42).
  - 지원 PostgreSQL·Supabase 간 호환, 다중환경 어댑터, 정상 복구·재시도는 유지한다. fallback이라는 이름이나 복수 경로만으로 제거하거나 환경·권한·정합성 요구를 줄이지 않는다.
  - DB 초기화·데이터 임의 삭제의 승인이 아니다. 영향·복구 방안을 제시해 별도 승인받는다(D-88 포함).
  - D-89의 옛 호출 호환, D-91의 옛 요청/클라이언트/schedule-preview 유지만 대체한다. 현재 필요한 무조건 이동·기본 관계 생성, 동시성·재배치 승인·정합성은 유지한다.
  - 선택적 코드 전반 감사에 잔존 호환 코드와 제거 근거·영향을 포함하되 구현·병합·릴리스의 새 필수 관문으로 만들지 않는다.

<a id="d-93"></a>

- **D-93 일정·시간 기록 편집의 원래 끝과 겹친 시각.** 손대지 않은 시작·끝은 저장된 시점·초를 보존한다. 고친 현지 시각이 두 번 존재하면 저장 전 ‘첫 번째 01:30 (UTC−04:00) / 두 번째 01:30 (UTC−05:00)’처럼 순서·UTC 차이를 함께 보여 선택받는다. 끝<시작은 서버가 400으로 거절한다. 구현 해석(사용자 결정 밖): 시간대 변경은 양끝을 고친 것으로 보고, 신규 생성의 겹친 시각은 D-81대로 앞선 것이다. 근거: 사용자(2026-10-22, #78·#72).

<a id="d-94"></a>

- **D-94 업무·일정 충돌 뒤 ‘내 입력으로 다시 저장’.** 내가 고친 칸만 적용하고 나머지는 서버 최신값을 유지한다. 같은 칸을 양쪽이 고쳤으면 두 값을 보여 덮어쓰기를 확인받는다. 일정의 날짜·시각·시간대·종일은 한 묶음이며 최신 판으로 다시 저장해 또 바뀌었으면 409다. 실패해도 입력을 보존한다. 범위는 업무 상세·일정 대화상자이고 문서 자동 3-way 병합 제외(X-11)는 유지한다. 구현 해석(사용자 결정 밖): 업무 시작/마감/마일스톤도 한 묶음, 담당자는 순서 없는 집합이다. 근거: 사용자(2026-10-22).

(2) 실제 편집자와 이동/대리 저장자를 구분해 기록하며 이동자가 직접 작성한 것처럼 표시하지 않는다. (3) 저장 실패는 이동을 409로 거절하고 편집을 보존한다. (4) 저장~이동 사이의 새 편집과 이동 실패·취소도 보존·시험한다. P-34 채택. 근거: 사용자(2026-10-22).

D-97의 명시적 버리기 원칙을 적용하고 #91 coordinator의 ‘경고 뒤 일반 재연결=동의’ 판단을 대체한다. 근거: 사용자(2026-10-22).

### 1.13 PostgreSQL 공통 지원 기준 (2026-10-22 추가)

<a id="d-100"></a>

- **D-100 PostgreSQL 최소 17과 검증한 메이저의 공통 구현.** 지원 목록에는 실제 검증한 메이저만 적고 ‘17 이상’으로 미래 메이저를 보장하지 않는다. 검증한 표준 PostgreSQL은 17·18이며 [환경별 결과](self-hosting.md#postgres-support)를 구분한다. 근거: 사용자(2026-10-22).
  - 표준 PostgreSQL·셀프호스트 Supabase·Supabase Cloud는 같은 제품 SQL·마이그레이션·RLS·권한을 쓴다. 차이는 초기 DB/역할 준비 권한과 연결/TLS/pooler 설정뿐이며 설치자에게 내부 RLS·함수 수정을 요구하지 않는다.
  - D-88의 Cloud 제외를 공통 구현의 설계·검증 대상으로 대체한다. Rust/OIDC/기존 저장소/검색은 유지하고 Supabase Auth/Storage/Realtime/Data API에 의존하지 않는다. 공식 권한 안내·로컬 제한권한 실행·실제 Cloud 실행을 구분한다.
  - 최소 미달은 bootstrap/migrate에서 변경 전에 설정 오류로 거절한다. 기존 읽기 전용 Cloud 경로로 버전을 확인할 수 있지만 원격 변경/업그레이드/역할·비밀번호 변경/제품 설치를 승인한 것은 아니다.
  - 백업·복구도 공통이며 session_replication_role은 초기 권한 조건이다. 제한 계정의 거부를 Cloud 복구 불가·기능 제외로 해석하지 않는다. 관리형 스키마·기본 역할·객체·데이터를 보존하며 데이터 삭제/이전은 별도 승인이다.
  - PG17 미만은 지원하지 않는다. 운영 DB 자동 업그레이드·PG18 데이터 볼륨에 PG17 이미지 연결을 금지한다. Supabase PG15→17은 [공식 절차](https://supabase.com/docs/guides/self-hosting/postgres-upgrade-17)를 따르되 실행은 별도 결정한다.

<a id="d-101"></a>

- **D-101 검색 날짜의 사용자 시간대 경계(P-24 채택).** 문서/항목/파일 수정 시각, 발생일 없는 기록 수정 시각, 시각 일정 시작은 사용자 시간대(D-81)의 하루 경계를 서버가 계산해 비교한다(DST의 23/25시간 포함). 마감일·종일 시작일·기록 발생일은 날짜 그대로 비교한다. 색인과 대체 SQL 의미를 맞추고 필요한 색인 변경·전체 재색인을 한다. 옛 호환용 day는 제거하되 현재 날짜 전용 필드는 유지한다(D-92). 구현: 개발 지침의 [검색 계약](development.md#search-contract).

<a id="d-102"></a>

- **D-102 작성자 검색의 색인 필터(P-25 채택).** 300개 후보를 받은 뒤 거르는 대신 작성자 조건을 색인 필터에 넣는다. D-39의 접근권한 원칙에 따라 서버가 결과의 최종 권한을 다시 검사하며 색인 필터로 대체하지 않는다. 대체 SQL과 의미를 맞추고 300개 뒤의 유효 결과를 찾는 회귀 시험을 둔다. 재색인은 D-101과 한 번에 한다. P-14는 관련 제안 기록이며 이 요구의 근거는 본 결정이다.

<a id="d-103"></a>

- **D-103 저장한 보기의 동시 수정 보호(P-26 채택).** 기존 수정은 기준 판 검사와 갱신을 같은 트랜잭션에서 필수 수행한다. 오래된 요청·재시도가 최신 설정을 덮지 못하며 충돌은 409+필요한 최신 정보, 웹은 입력 보존이다. 생성과 수정을 구분하고 무조건 덮어쓰는 옛 호환 경로는 제거한다(D-92). P-26의 마지막 저장 우선은 채택하지 않았다.

<a id="d-104"></a>

- **D-104 항목 정보의 동시 수정 보호(P-30 채택).** 적용 필드를 명시하고 모든 해당 수정 경로에 기준 판 검사를 둔다. 오래된 수정은 409, 웹은 입력을 보존하고 최신본 확인·다시 편집을 제공한다. 구현 해석(사용자 결정 밖)의 범위는 제목/설명/공개와 항목 프로필 모두이며 상세 필드는 [SQL 정책 계약](development.md#version-contract)이다. D-94가 항목에 이미 승인된 것은 아니고 이 결정으로 판 검사를 추가한다. 문서 자동 3-way 병합(X-11)·범용 충돌 틀로 확대하지 않는다.

<a id="d-105"></a>

- **D-105 CSV 업무 생성의 원자성(P-31 채택).** 생성 후 별도 수정하는 대신 업무 한 건의 모든 필요한 칸을 서버가 확인해 한 트랜잭션으로 저장한다. 실패에 제목만 있는 업무·일부 관계를 남기지 않고 응답 유실 재시도도 요청 id 멱등 계약으로 중복 생성하지 않는다. 원자성은 업무 한 건이며 CSV 전체 성공/실패로 넓히지 않고 행별 결과 안내를 유지한다.

<a id="d-106"></a>

- **D-106 보관 항목의 자기 댓글 지우기(P-28 현행 유지).** 개인 내용 회수를 위해 본인 댓글 지우기만 허용하며 수정·새 댓글·남의 댓글 지우기로 넓히지 않는다. 보관된 항목·모듈의 업무/문서 권한은 read로 낮아져 소유 권한자도 남의 댓글은 이미 403(42501), 본인은 204이며 목록의 지우기 표시도 같은 권한을 따른다. 수정·스레드 해결·새 댓글은 409다. **권한 변경·403→409 변경이 아니고 코드·SQL도 바꾸지 않는다.** 기존 동작을 고정하는 시험만 추가했다. 전체 호출 경로·시험은 [SQL 정책 계약](development.md#version-contract).

- **P-29·P-35 보류·추적.** P-29(시간 기록 길이 상한): 이번에 도입하지 않는다. 일정의 366일 상한을 그대로 옮기지 않으며 기존 긴 기록을 지우거나 자르지 않는다. 이미 고친 집계 비용(#55, 감사 S20, 기간 안의 날만 펼침)과 정책상 허용 범위(길이 상한 여부와 값)는 별개이며 후자는 미정이다. P-35(반복 회차 맞추기의 항목별 트랜잭션): 보류한다. 이번 SQL 정리에서 부분 커밋·실패·재시도 의미를 바꾸지 않고 0089의 교착 수정은 유지한다. 남은 잠금 보유 시간 개선은 후속 항목으로 추적한다. 추적 이슈: P-29 fvoci/GroundZero#96, P-35 fvoci/GroundZero#95. 둘 다 2절에 제안으로 남으며 해결된 것으로 보지 않는다.

## 2. 미승인 제안 (검토자)

P 번호는 제안 이력을 보존한다. 채택·대체·기각·보류는 표시된 범위에 한하며, 본문의 겹치는 구현만으로 새 승인 사실을 만들지 않는다. 현행 요구는 연결된 D를 따른다. 표시가 없는 제안은 미승인이다. [제안 당시 상세·재현](https://github.com/fvoci/GroundZero/blob/abd545a250ff1fd9cc166b3c078c4dff76846724/docs/decisions.md#L262-L336)은 역사 기록이다.

- **P-01** 공통 코어+모듈별 메타데이터/보기, 공통 항목 표+유형별 확장 구조.
- **P-02** 모듈별 최소 사용자 흐름을 단계적 검증 기준으로 명시.
- **P-03** `[채택 → D-48]` 모듈별 항목·업무·문서 공통 번호열.
- **P-04** `[기각 → D-49]` 개인 노트의 공유 금지.
- **P-05** 시간 기록·타이머·즐겨찾기·최근 항목을 사용자 소유 영역으로.
- **P-06** 자료+버전 모델을 모든 모듈의 공통 첨부 모델로.
- **P-07** 분석 기록에 외부 URL+커밋/버전 참조 허용.
- **P-08** 자료 버전별 체크섬으로 무결성·동일 파일 확인.
- **P-09** `[채택·확장 → D-56]` 참조 중 자료 버전의 삭제 제한.
- **P-10** 체크 항목의 업무 전환·기존 업무/강의 회차 연결. 연결 대상이 정본이고 서버 수정권한 검사·실패 표시 복구·본인 강의 진도만 변경을 제안했다. 아직 제안이다.
- **P-11** `[대체 → D-53]` CRDT OFF의 충돌 처리.
- **P-12** Markdown 원본을 지원 블록이 제한된 보조 모드로 명시(표·수식·멘션·체크 참조의 왕복 손실 가능).
- **P-13** CRDT의 텍스트/JSON 투영(리비전·diff·검색·멘션)을 설계 항목으로 명시.
- **P-14** 검색 결과의 서버 권한 재검사. 관련 확정 요구는 D-39·D-102이며, 이 P 번호의 제안 이력과 구분한다.
- **P-15** 모듈 보관·삭제 뒤 참조 키를 별칭으로 예약.
- **P-16** 표마다 공간 소유/사용자 소유 RLS 범위를 명시.
- **P-17** 진도는 개인별·업무 상태는 공유라는 일반 규칙을 스터디에 적용.

- **P-20** 업로드 완료·업무 생성·타이머 시작의 클라이언트 멱등 키를 공통 원칙으로.

- **P-22** 홈 Up Next용 모듈 공통 ‘오늘 할 일’ 인터페이스.

- **P-29** `[보류·추적 → 1.14, #96]` 시간 기록 길이 상한. 값·도입 여부는 미정이며 일정의 366일 제한을 옮기거나 기존 기록을 자르지 않는다. #55의 집계 비용 수정과 별개다.

## 3. 열린 항목

### 3.1 사용자 결정

공개·공유·삭제·보존·권한·사용 경험·비용은 사용자 결정이다. 구현 선택을 이유로 승인 사실을 추가하지 않는다.

- **O-30** `[해소 → D-68·D-72]` 의존성 라이선스 승인. 초기 FAIL·미승인 목록은 [당시 기록](https://github.com/fvoci/GroundZero/blob/abd545a250ff1fd9cc166b3c078c4dff76846724/docs/decisions.md#L344)이며 현재 검사 결과가 아니다.
- **O-37** `[해소 → D-86]` 여섯 서체 파일의 OFL-1.1 예외. [승인 파일·판·출처·SHA-256·저작권 원문](https://github.com/fvoci/GroundZero/blob/abd545a250ff1fd9cc166b3c078c4dff76846724/docs/decisions.md#L345-L354)을 보존한다. 이 원문에서 제안했던 preload·선택지는 현행 로딩 정책이 아니며 D-86을 따른다. 서체만 별도 판매하지 않고 앱과 함께 배포한다. 모든 사본에 저작권·라이선스를 보존하며 원본을 변환하지 않는다. D2Coding/D2Coding-Bold는 예약 이름, Noto 원문의 예약 이름은 없으며 상표는 서체 이름 표시 외 제품 이름·홍보에 쓰지 않는다. OFL 적용은 서체 파일이며 앱 코드·문서로 확대하지 않는다.
- **O-27** 자체 공개 라이선스는 의존성 정책과 별도인 제품·사업 결정이다. 사용자가 나중에 결정하기로 했으며 검토자가 권장안을 정하지 않는다. 공개 전 결정하되 구현의 차단 항목은 아니다.

### 3.2 기술 설계

D-43·D-47에 따라 근거·권장안·대안을 검토해 구현한다. 아래 상태는 기록된 상태를 보존하며, 열린 설계 항목만 보고 관련 구현이 전혀 없다고 단정하지 않는다. 현행 코드·D와 적용 범위를 함께 확인한다.

- **O-04** 체크리스트 저장/본문-폼 연결/재가져오기 추가·교체. 권장안은 독립 항목을 본문 ID로 참조하고 가져오기는 기본 추가·명시적 교체, 대안은 본문 파싱 정본이다(D-30).
- **O-08a** CRDT 저장 방식. 권장안은 문서별 Yjs 업데이트 로그+주기 스냅샷·서버 JSON 투영(P-13), 대안은 로그 없는 스냅샷만 저장이다. OFF 충돌은 D-53, 엔진 선택은 D-70과 구분한다.
- **O-09** 공간 간 공유·이동·개인 소유의 RLS 설계. 권장안은 소유 공간/사용자 또는 명시적 공유, 세부 객체권한은 앱 검사, 실행/마이그레이션 역할 분리다. RLS 생략 대안은 D-08과 맞지 않는다. 초기 멤버십 RLS 진행 기록과 현행 역할/함수 계약(D-88)을 구분한다.
- **O-11** rhwp의 HWP 5.x/HWPX/구형 HWP 형식별 실제 호환성과 실패 대안. 표/수식/그림 샘플로 확인하며 실패 형식의 변환 경유·미지원은 기능/서비스 범위에 맞춰 별도 판단한다.
- **O-19** `[해소: 구현, 권장안 채택]` 한 바이너리의 worker, FVOCI_ROLE=all|api|worker(기본 all), PostgreSQL 작업 기록. 별도 서비스/큐는 추가하지 않았고 작업 DB 계정도 분리하지 않았다.
- **O-25** `[해소: 구현, 권장안 채택]` 표준 OIDC 클라이언트와 설정 가능한 외부 제공자, 선택 프로필의 Keycloak이다. 항상 내장 Keycloak을 요구하지 않는다.
- **O-10** Office 뷰어 비교 평가. 샘플의 표/그림/수식/여러 페이지와 렌더링·자원·배포 비용을 비교한다. 브라우저 뷰어/서버 변환 선택 중 새 서비스는 사용자 결정이며 후속 D-71·D-74를 적용한다.
- **O-31** `[해소: 구현, 권장안 채택]` 고정 SeaweedFS·독립 버킷/tmpfs로 multipart 생성/파트/완료/중단/목록/재개를 검증하는 구성. 로컬 결과를 R2 결과로 확대하지 않는다.
- **O-33** `[해소: 구현]` @A/DEV-1의 A는 내가 속한 공간 이름의 앞부분이다. 중복 이름 모두를 후보로, UUID 기반 배지와 동명 시 끝 네 글자로 구분하고 선택은 내부 ID로 보존한다. 새 전역 고유 이름/키를 요구하지 않는다. 배지 색 사용자 선택은 아직 없다는 구현 제한을 D-17과 구분한다.
- **O-34** `[해소: 사용자 지시, D-56 일관성 수정]` 살아 있는 기록·문서가 참조한 버전의 휴지통 묶음은 자동 만료 삭제를 건너뛰고 ‘만료(참조 중)’로 남긴다. 관리자 직접 영구 삭제는 기존대로다. 0046 이전 삭제 동작은 현행이 아니다.
- **O-35** `[해소 → D-69]` 참조 때문에 보존한 만료 묶음 되살리기.
- **O-36** `[해소 → D-76]` HWP·HWPX 전용 WASM과 범위 한정 보안 예외. [채택 전 검증·승인 요청](https://github.com/fvoci/GroundZero/blob/abd545a250ff1fd9cc166b3c078c4dff76846724/docs/decisions.md#L396)은 과거 기록이다.
- **O-26** 운영 한도 기본값(D-52). 예상 사용량·통합 시험 근거로 제안해 설정 파일에 두고 임의 코드 상수로 정하지 않는다.
