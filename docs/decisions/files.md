# 결정 기록 · 파일·첨부·미리보기·저장소

[결정 기록 색인](../decisions.md)의 한 주제다. 번호·앵커(`#d-xx`)는 색인 전체에서 고유하다. 아래 "현재 규칙 요약"은 이 주제의 유효한 규칙을 줄인 것이고, 정본은 그 아래 조항이다. 조항 안의 "개정 2026-10-25"는 그날 바뀐 문구이며 이전 문장은 조항의 원문 연결 또는 [개정 전 판](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/decisions.md)에서 본다.

## 현재 규칙 요약

- 파일은 S3 호환 또는 로컬 저장소에 청크 업로드·재개·무결성 확인으로 올리고 다운로드 권한을 검사한다(D-06).
- 운영은 Cloudflare R2, 로컬·CI는 고정 SeaweedFS이며 로컬 결과를 R2 검증으로 보지 않는다(D-61).
- Office 미리보기는 브라우저 구현 우선이고 PPTX는 @aiden0z/pptx-renderer, HWP·HWPX는 rhwp 전용 WASM이다(D-54, D-71, D-74, D-76).
- 미리보기 관련 보안 예외는 해당 빌드에 한정하고 사유·제거 조건을 기록한다(D-76).

## 조항

<a id="d-06"></a>

- **D-06 파일 저장과 업로드.** S3 호환 또는 서버 로컬 저장소. 청크 업로드·재개·재시도·무결성 확인, 완료 요청 중복 방지, 취소·만료 잔여 데이터 정리, 다운로드 권한 검사를 제공한다. Cloudflare 경유 시 개별 요청 한도 안에서 전송하며 완료 때 전체 파일을 다시 보내지 않는다. 파일 크기·총 저장량은 운영 설정이다(D-52). 근거: 초안 §2·§17.

<a id="d-54"></a>

- **D-54 Office 미리보기 선택 방식.** LibreOffice를 미리 확정하지 않는다. DOCX·XLSX·PPTX의 표·그림·수식·페이지 재현과 자원 사용을 비교해 선택한다. 비교는 기술 설계(O-10), 새 서비스 추가는 사용자 결정(D-47)이다. 후속 선택은 D-71·D-74. 근거: 사용자.

<a id="d-61"></a>

- **D-61 S3 호환 저장소 대상.** 운영은 Cloudflare R2, 로컬·CI 시험은 고정 SeaweedFS(Apache-2.0)를 우선한다. multipart·완료·중단·재개와 라이선스를 확인하고 독립 버킷·볼륨으로 격리한다. 자체 S3 서버는 만들지 않으며 로컬 파일 지원을 유지한다. 로컬 성공은 R2 검증 완료가 아니고 실제 연결·자격 증명·비용을 쓰는 검증은 별도 요청 대상이다. O-29 해소, 시험은 O-31. 근거: 사용자.

<a id="d-71"></a>

- **D-71 Office 미리보기는 브라우저 구현 우선.** DOCX·XLSX·PPTX 대표 샘플의 표·그림·글꼴·페이지/슬라이드를 확인해 충족하는 범위부터 구현한다. HWP·HWPX는 rhwp를 유지하고 실제 형식·렌더링을 검증한다. 새 라이선스는 별도 확인, Gotenberg·LibreOffice는 브라우저 방식의 구체적 부족을 확인한 뒤 제안한다. R2 실검증은 승인된 대상·자격 증명이 준비될 때까지 NOT RUN이다. D-54·O-10의 진행 방식. 근거: 사용자(2026-10-17).

<a id="d-74"></a>

- **D-74 PPTX 미리보기는 브라우저에서 @aiden0z/pptx-renderer 1.3.0으로.** 종속 tslib 2.3.0(0BSD, echarts 6.1.0 경유)·mtx-decompressor(MPL-2.0)를 패키지·판 단위로 허용한다. 렌더러 번들에는 수정 없는 mtx-decompressor **1.4.2**, 설치 목록에는 선언만 있는 1.8.0이 있으며 검사 예외는 1.8.0에 둔다. 번들의 1.4.2와 ECMA-376 유래 자료·ECMA 고지까지 승인 범위다. 렌더러 고지(1.4.2 소스 입수 경로 포함)와 MPL-2.0 원문을 제3자 고지에 넣는다. 다운로드 권한자만, DOCX처럼 같은 출처가 아닌 격리 iframe에서 표시한다. 근거: 사용자(2026-10-17), D-71 후속.

<a id="d-76"></a>

- **D-76 HWP·HWPX 미리보기는 rhwp 전용 WASM으로.** 상위 rhwp `515bd72dcde0`에서 PDF 가져오기를 끈다(`--no-default-features --features console_error_panic_hook`). 최초 잠금 변경은 chacha20 0.10.2(회수 해소)·unicode-ident 1.0.27(빌드 전용, D-72)이며 현재 고정 입력은 [Cargo.lock](../../deploy/rhwp/Cargo.lock)이다. 이후 [#109](https://github.com/fvoci/GroundZero/pull/109)에서 반영한 ctutils 0.4.4 보안 갱신은 이 최초 변경 목록과 구분한다.
  - 예외는 **HWP·HWPX 미리보기 빌드에 한정**한 유지 중단 알림 RUSTSEC-2026-0206(rustybuzz 0.20.1)·RUSTSEC-2026-0192(ttf-parser 0.25.1)뿐이다. 사유·제거 조건을 기록하고 다른 취약점·회수·라이선스 검사를 유지한다.
  - Rust 1.93.1·wasm32·wasm-bindgen-cli 0.2.127은 전용 빌드 단계에서만 쓴다. 앱 툴체인을 낮추지 않는다. 소스·잠금·기능·도구가 같으면 WASM을 재사용하고 입력 변경 때 다시 빌드한다.
  - 미리보기를 열 때만 불러오고 압축·캐시를 쓴다. Web Worker·파일 크기/시간 한도·취소로 큰 파일·손상이 화면을 멈추지 않게 한다. 배포할 WASM으로 견본과 손상 파일 거부를 확인하고 고지를 넣으며 최적화 전 크기와 실제 압축 전송 크기를 구분한다.
  - O-36 해소. 근거: 사용자(2026-10-17); [최초 결정 원문](https://github.com/fvoci/GroundZero/blob/abd545a250ff1fd9cc166b3c078c4dff76846724/docs/decisions.md#L164).
