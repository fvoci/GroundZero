# 결정 기록 · 문서 편집·리비전·공동 편집·내보내기

[결정 기록 색인](../decisions.md)의 한 주제다. 번호·앵커(`#d-xx`)는 색인 전체에서 고유하다. 아래 "현재 규칙 요약"은 이 주제의 유효한 규칙을 줄인 것이고, 정본은 그 아래 조항이다. 조항 안의 "개정 2026-10-25"는 그날 바뀐 문구이며 이전 문장은 조항의 원문 연결 또는 [개정 전 판](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/decisions.md)에서 본다.

## 현재 규칙 요약

- Tiptap 블록 편집이 기본, Markdown 원본 편집은 보조 입력이며 모드 전환에 내용을 잃지 않는다(D-27).
- 문서 저장은 리비전 단위이고 `base_revision` 충돌은 409, 선택적 `If-Match`는 412다. 실시간 OFF 충돌은 초안 보존 후 차이 확인이며 자동 3-way 병합은 제외한다(D-53, D-62).
- 실시간 공동 편집은 Rust/yrs이며 권한 재확인 주기는 1~3,600초 설정이고 이동 전 미저장 편집은 대리 저장한다(D-70, D-95). 다시 연결 시 초안은 명시적으로만 버린다(D-99).
- 저장 요청은 편집을 시작한 기대 사용자와 실제 사용자가 다르면 거절하며 문서와 업무 쓰기 전부에 적용한다(D-96). 미저장 입력은 어느 칸이든 같은 규칙으로 보존하고 떠날 때 경고한다(D-27).
- 문서 복원은 연결 업무 완료·강의 진도를 되돌리지 않는다(D-29, D-58).
- 체크리스트는 편집기 없이도 같은 데이터로 입력하며 일반 체크가 업무·강의 완료를 자동 수행하지 않는다(D-30).
- 한 건 Markdown·PDF 내보내기는 열람 권한과 `allow_copy`를 검사하고 비공개 이름·데이터를 내보내지 않는다(D-75, D-115).
- 수정이 있는 대화상자는 닫을 때 확인한다(D-97).

## 조항

<a id="d-27"></a>

- **D-27 문서 편집 경험.** Tiptap 노션형 블록/리치 편집을 기본으로 Markdown 원본 편집(추가 입력 방식)·읽기 미리보기·문서 트리/템플릿·표/코드/수식/이미지/첨부·댓글/멘션/공동 노트·링크/역방향 링크·자동 저장/상태 안내·미저장 초안 보호·리비전/diff/복원을 제공한다. 모드 전환에 내용을 잃지 않고 Markdown 지식을 필수로 하지 않는다. 공동 편집은 공간별 선택이며 OFF에서도 충돌과 차이를 확인해 반영한다. 위키·모듈 문서 모두 리비전/diff/복원 대상이고 업로드 파일 내부 diff 제외(X-03)와 구분한다. 근거: 초안 §8·사용자.
  - 개정 2026-10-26: 미저장 초안 보호는 모든 텍스트 입력 칸에 한 규칙으로 적용한다: 사용자별·탭별 브라우저 키, 되살리거나 버리거나 서버 내용과 같아질 때까지 보존(별도 만료 없음), 화면을 떠날 때 경고. 문서 본문·댓글, 업무 폼·새 업무 제목·관계 편집·체크리스트 새 항목·업무 댓글이 모두 대상이며 D-125의 이탈 취소 패턴 하나로 구현한다. 근거: 사용자(2026-10-26 ⑱).

<a id="d-29"></a>

- **D-29 복원 규칙 설계.** 문서 복원과 연결 업무·수강 진도 상태 변경을 구분한다(D-58). 근거: 사용자.

<a id="d-30"></a>

- **D-30 체크리스트 공통 입력.** 편집기가 없어도 체크박스·내용 입력으로 추가/수정/삭제/완료 변경을 제공한다. 편집기 본문과 별도 폼에서 같은 목록을 보여주면 동일 항목·상태를 참조하고 중복 저장하지 않는다. 붙여넣은 Markdown의 완료 상태·내용을 일반 입력 영역으로 가져와 사용자가 확인·수정한다. 모든 목록을 문서 본문이나 업무로 강제하지 않고, 일반 체크가 업무 생성·강의 완료를 자동 수행하지 않는다. 업무 전환·기존 업무/회차 연결은 제안(P-10), 저장/연결/재가져오기 설계는 O-04다. 근거: 초안 §9·사용자.

<a id="d-53"></a>

- **D-53 실시간 OFF 충돌 처리.** 초안을 보존하고 서버 최신본과 차이를 보여 수정 후 재저장하거나 복사본으로 보존한다. 확인 없는 덮어쓰기·자동 3-way 병합은 제외한다(X-11). 업무·일정 폼의 재저장은 D-94다. O-08b 해소, P-11 대체. 근거: 사용자.

<a id="d-58"></a>

- **D-58 문서 복원 규칙.** 문서 자체 내용·체크리스트와 외부 업무 참조를 구분한다. 문서를 복원해도 연결 업무 완료·강의 진도는 되돌리지 않는다. O-17 해소. 근거: 사용자.

<a id="d-62"></a>

- **D-62 첫 사용자 흐름의 문서 저장 경계.** Tiptap JSON의 리비전 저장은 단계적 검증이며 공동 편집 완료가 아니다. CRDT 연동 때 문서·편집기를 재작성하지 않도록 불변 UUIDv7·본문 스키마 판·리비전 번호·본문/체크리스트/외부 업무 참조의 저장 경계를 분리한다. 근거: 사용자.

<a id="d-70"></a>

- **D-70 실시간 공동 편집은 Rust/yrs로.** 별도 Node 서비스는 두지 않는다. yrs의 smallstr 권고 RUSTSEC-2026-0215가 **유지 중단 알림이고 취약점이 아님을 공식 원문으로 확인한 경우에만** 그 ID 하나를 cargo-deny 예외로 둔다. 사유·제거 조건을 남기고 다른 보안 검사는 유지한다. 원문이 다르면 예외 적용 전에 보고한다. 근거: 사용자(2026-10-17).
  - 개정 2026-10-26: 공동 편집 세션의 권한 재확인 주기는 서버 설정이며 범위는 1~3,600초다. 권한 철회는 최대 그 주기만큼 늦게 연결이 끊기며 이 지연을 수락한다. 기본값은 서버 설정 문서에 적는다. 근거: 사용자(2026-10-26 추가 3).

<a id="d-75"></a>

- **D-75 문서 한 건의 Markdown·PDF 내보내기.** 위키·모듈·개인·공유 문서를 선택한 저장 리비전 기준으로 내보낸다. 열람권한과 소유자의 복제·내보내기·다운로드 허용(D-115, 소유자 외 모든 권한에 적용, 개정 2026-10-25)을 검사하고 미저장 편집이 있으면 먼저 저장하거나 저장된 판을 쓸지 알린다. Markdown은 제목·본문·표·코드·체크 상태·링크를 보존하고 불가한 표현을 조용히 버리지 않는다. 이식용 ZIP은 허용된 그림·첨부만 담아 상대경로로 연결한다. PDF의 한글·표·그림·코드·수식·쪽 나눔과 글꼴 임베딩/재배포 조건을 확인한다. @참조는 권한 있는 대상만 제목·링크로 바꾸고 비공개 이름·데이터를 내보내지 않는다. 연결 업무·진도는 내보내는 시점의 표시 상태만 담고 원본을 바꾸지 않는다. 위키/하위 문서 일괄 내보내기는 별도 범위다. 기존 변환·도구를 재사용하고 중복 문서 모델을 만들지 않는다. 근거: 사용자(2026-10-17).

<a id="d-95"></a>

- **D-95 실시간 문서 이동 전 미저장 편집의 대리 저장.** 열린 방과 닫힌 방의 저장 대기 편집을 모두 이동 전에 리비전으로 남긴다. 편집자가 새 자리에서 저장할 수 없으면 옮긴 사람이 대신 저장한다. (1) 이동 권한을 검증한 서버 내부 처리만 허용하고 편집자 권한을 넓히지 않는다. (2) 실제 편집자와 이동/대리 저장자를 구분해 기록하며 이동자가 직접 작성한 것처럼 표시하지 않는다. (3) 저장 실패는 이동을 409로 거절하고 편집을 보존한다. (4) 저장~이동 사이의 새 편집과 이동 실패·취소도 보존·시험한다. P-34 채택. 근거: 사용자(2026-10-22).
  - author/edited_by, 방 안·밖 복원 작성자, 권한·잠금·재확인·남는 경합과 상한은 **사용자 결정과 구분한 구현 해석·제한**이며 [제거 전 개발 계약](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/development.md#live-document-preservation)에 기록돼 있다(D-127). 최초 인계의 미완료 표시는 현재 요구의 삭제가 아니다. 상세 [구현·검증 이력](https://github.com/fvoci/GroundZero/blob/abd545a250ff1fd9cc166b3c078c4dff76846724/docs/decisions.md#L215-L225)을 보존한다.

<a id="d-96"></a>

- **D-96 저장 요청의 기대 사용자 확인.** 서버가 편집/초안을 시작한 기대 사용자와 실제 인증 사용자를 비교해 다르면 쓰기 전에 거절한다. 기대값은 신원·권한 근거가 아니고 지금 로그인한 사용자로 조용히 바꾸지 않는다. 웹은 자동 재시도를 멈추고 원래 입력을 보존하며 다른 계정 화면에 노출하지 않는다. 자동/직접 저장·재시도와 값 누락 처리, 실시간 등 별도 경로의 적용 여부·위험을 명시하고 옛 호환 경로는 두지 않는다(D-92). 근거: 사용자(2026-10-22).
  - 개정 2026-10-26: 업무 쓰기 전부(저장·칸반 이동·관계·체크리스트·반복·CSV 가져오기)에도 기대 사용자 헤더가 필수이며 불일치는 409 account_changed다. 웹의 처리는 문서와 같다. "별도 경로의 적용 여부"에서 업무 경로는 적용으로 확정한다. 근거: 사용자(2026-10-26 ⑫).
  - 구현 해석(사용자 결정 밖): x-fvoci-expected-user 헤더, 세션 없음 401→헤더 없음/복수/UUID 오류 400→다른 사용자 409 account_changed 순서다. /api/me 사전 확인은 앞단 방어로 유지한다. 경로별 범위·제외 이유는 [제거 전 개발 계약](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/development.md#expected-user).
  - 실시간 expected_user 적용은 coordinator의 구현 지시다. 누락/형식 오류는 업그레이드 전 400, 불일치는 연결 후 4412다. 이미 열린 연결은 원래 사용자 세션이 끝날 때까지 쓸 수 있다는 위험을 구분한다. #88의 다시 읽기 실패 안전 상태 등 나머지는 이 결정 구현만으로 닫지 않는다.

<a id="d-97"></a>

- **D-97 고친 업무·일정 대화상자 닫기.** 수정이 있으면 Esc·바깥 클릭·닫기에서 ‘계속 편집 / 변경 버리고 닫기’를 확인받고 없으면 바로 닫는다. 확인 창 Esc는 편집·초점을 되돌린다. 저장 중·409·다시 열기·늦은 응답으로 다른 세션을 닫거나 덮지 않고 명시적 버리기 때만 지운다. 브라우저 종료·모든 화면 이동 보호는 아니다. 근거: 사용자(2026-10-22).
  - 구현 해석(사용자 결정 밖): 공통 DiscardChangesConfirm을 쓰고 저장 중에는 닫기/질문 없이 입력을 잠근다. 서버가 제거하는 앞뒤 공백만 바뀐 것은 수정으로 보지 않는다.
  - 당시 구현 범위 밖: 반복 규칙, 체크리스트 새 항목/선행·상위 업무/지연일 등 링크 입력/댓글 초안/하위 업무 만들기, 삭제 뒤 이동·브라우저 뒤로 가기, CalendarTaskDialog. 대화상자 안 다른 업무 열기는 후속 #91에서 같은 확인을 거치게 했다. [당시 범위·검증](https://github.com/fvoci/GroundZero/blob/abd545a250ff1fd9cc166b3c078c4dff76846724/docs/decisions.md#L230-L233).
  - 개정 2026-10-26: 입력 보존 범위는 D-27의 모든 텍스트 입력 칸으로 확장한다. 위의 당시 제외 목록과 화면 이동 보호의 제한은 현재 범위의 제외 근거가 아니다. 체크리스트 새 항목·업무 댓글·관계 입력도 초안 보존과 이탈 경고 대상이며 D-125의 공통 이탈 취소 패턴을 따른다. 대화상자의 명시적 버리기·취소 원칙은 유지한다. 근거: 사용자(2026-10-26 ⑱).

<a id="d-99"></a>

- **D-99 미저장 실시간 편집의 다시 연결과 버리기.** 일반 다시 연결은 초안 저장을 재시도하고 실패하면 제목·본문·화면을 유지한다. 실패 경고 열람은 버리기 동의가 아니다. 버리기는 별도 ‘편집 버리고 다시 연결’에서 미저장 손실을 확인받으며 취소·Esc는 편집으로 돌아간다. 다른 문서/계정/보호된 reserved 초안을 지우거나 덮지 않는다. 계속된 실패·reserved 거절·취소/확인·인계 입력 차단을 회귀 시험·실제 브라우저로 확인한다. D-97의 명시적 버리기 원칙을 적용하고 #91 coordinator의 ‘경고 뒤 일반 재연결=동의’ 판단을 대체한다. 근거: 사용자(2026-10-22).
  - 구현은 #94(병합 200292c). 자리에서 다시 열 때 이 탭의 기존 초안을 삭제/덮어쓰기하지 않고 선택 목록이나 보호 상태로 두는 것은 구현 해석이다. [검증·NOT RUN 기록](https://github.com/fvoci/GroundZero/blob/abd545a250ff1fd9cc166b3c078c4dff76846724/docs/decisions.md#L237-L238).
