# 결정 기록 · 조직·역할·권한·공유

[결정 기록 색인](../decisions.md)의 한 주제다. 번호·앵커(`#d-xx`)는 색인 전체에서 고유하다. 아래 "현재 규칙 요약"은 이 주제의 유효한 규칙을 줄인 것이고, 정본은 그 아래 조항이다. 조항 안의 "개정 2026-10-25"는 그날 바뀐 문구이며 이전 문장은 조항의 원문 연결 또는 [개정 전 판](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/decisions.md)에서 본다.

## 현재 규칙 요약

- 계층은 서버 › 조직 › 워크스페이스 › 모듈 › 항목이고, 한 계정은 여러 조직에 속할 수 있으며 개인 화면은 현재 조직 범위다(D-111, D-13).
- 서버 관리자(`server_admins`)와 조직 관리자는 메타데이터만 다룬다. 조직 관리자는 워크스페이스 삭제·복원·소유자 이전·소유권 제안을 하고 "관리자로 참여"한 공간에서만 내용을 본다(D-112, D-21).
- 워크스페이스 역할은 관리자·멤버·읽기 전용이다. 읽기 전용은 댓글·본인 진도를 포함해 쓰지 않고, 역할이 개별 공유의 상한이다(D-20, D-112). 워크스페이스 초대는 관리자가 보내고 조직 밖 사람이 수락하면 조직 멤버로 자동 가입한다(D-112). 보관 항목에서 본인 댓글 지우기는 회수라 허용하고 관리자는 공유·링크·설정을 바꿀 수 있다(D-106, D-113).
- 접근 등급(none/read/write/owner)은 SQL의 `app_access` 하나가 계산하고 RLS·서버·웹이 모두 그 결과를 쓴다(D-113).
- 개별 공유·참조·이동·복제는 같은 조직 안에서만 하며 공유 요청은 웹이 현재 조직을 보낸다. 공간에서 제거되면 그 공간의 개별 공유·담당이 풀리고, 조직에서 빠지면 조직 안 전부가 풀린다(D-114, D-24, D-59).
- 복제·내보내기·다운로드 허용은 `allow_copy` 하나이며 소유자 외 모든 권한에 적용된다(D-115).
- 비로그인 공개 링크는 명시 활성화·만료·철회를 지원하고 조직 관리자가 끌 수 있다(기본 켜짐)(D-20, D-114).
- 공간 관리자는 자기 공간의 비공개 문서도 보지만 개인 노트는 누구에게도 비공개다. 개인 노트는 계정 소유이고 공유만 같은 조직 사람에게 한다(D-21, D-22, D-40, D-49).

## 조항

<a id="d-08"></a>

- **D-08 SaaS·격리·운영 원칙.** 소유 워크스페이스를 명시하고 공간 간 공유는 명시적 권한으로 처리한다. 관리자는 자기 공간만 열람하며 개인 시간 기록의 비공개를 유지한다. RLS와 앱 권한 검사를 함께 설계하고(O-09), 앱 실행 역할과 운영·마이그레이션 역할을 분리한다. 검색·첨부·캐시·실시간·백그라운드 작업도 격리하며 셀프호스트와 SaaS의 핵심 데이터·권한 의미를 같게 한다. 개정(2026-10-25): 격리 단위는 조직이고(D-111), 서버 관리자·조직 관리자는 메타데이터만 다루며(D-112), 공유·이동은 같은 조직 안이다(D-114). 근거: 초안 §19.

<a id="d-13"></a>

- **D-13 조직과 워크스페이스.** 워크스페이스는 사람·권한·콘텐츠를 묶는 공간이고 모든 워크스페이스는 조직 하나에 속한다(D-111). 한 사용자가 여러 조직·여러 공간에 속할 수 있다. 공간에는 위키·프로젝트/연구/스터디/강의/취미 모듈·검색·최근 항목·즐겨찾기를 두고, 홈·내 업무·알림함·시간 기록은 현재 조직 범위의 개인 화면이다(D-120). 근거: 초안 §3; 개정 2026-10-25 사용자([원문](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/decisions.md#d-13)).

<a id="d-20"></a>

- **D-20 역할과 기본 권한.** 워크스페이스 역할은 관리자·멤버·읽기 전용이며(D-112) 초대·제거·역할 변경·그룹 관리를 제공한다. 새 항목은 기본 비공개이며 공간 공개를 선택할 수 있다. 읽기 전용은 읽기만 하고 댓글을 포함한 쓰기를 하지 않는다. 역할이 개별 공유의 상한이다: 읽기 전용에게 수정 공유를 줄 수 없고 개별 공유는 비공개 문서를 열어 주는 용도다. 재공유는 소유자·공유 관리 권한자만, 복제·내보내기·다운로드 허용은 소유자가 하나의 설정으로 정하며 소유자 외 모든 권한에 적용한다(D-115). 상위 공유의 기본 상속은 항목·공간 역할을 뜻하며 부모 문서의 공유는 상속하지 않고 문서 비공개 예외를 허용한다. 비로그인 공개 링크는 명시적 활성화·만료·철회를 지원하며 조직 관리자가 조직 단위로 끌 수 있다(D-114). 근거: 초안 §7; 개정 2026-10-25 사용자([원문](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/decisions.md#d-20)).
  - 개정 2026-10-26: 읽기 전용의 쓰기 금지는 본인 강의·스터디 진도 저장(`app_set_episode_progress`·`app_set_unit_progress`)에도 적용한다. 읽기 전용은 진도를 남기지 못하며 D-78의 "진행은 개인별"은 멤버 이상에 해당한다. 근거: 사용자(2026-10-26 ⑧).

<a id="d-21"></a>

- **D-21 관리자 열람.** 워크스페이스 관리자는 해당 공간의 모든 문서를 열람하며 그 범위를 사용자에게 명확히 알린다. 서버 관리자는 메타데이터만 보고 어떤 내용도 보지 않으며, 조직 관리자는 메타데이터만 보되 "관리자로 참여"한 공간에서만 내용을 본다(D-112, 개정 2026-10-25). 비공개 예외는 D-40, 감사로그는 D-57. 근거: 초안 §7·선택 2번·사용자.

<a id="d-22"></a>

- **D-22 개인 노트.** 공간 관리자에게도 비공개인 개인 노트를 제공한다. 서버·DB 운영자에게 비밀을 보장하는 암호화는 확정 요구가 아니다(H-01). 소유·공유는 D-49·D-59로 초안 §21의 미정을 대체한다. 근거: 사용자.

<a id="d-23"></a>

- **D-23 원본 공유와 복제.** 소유자는 특정 사람에게 읽기·수정 권한을 줄 수 있고 공유받은 사람의 수정은 원본에 반영된다. 복제는 독립 사본이며 이후 자동 동기화하지 않는다. 개별 공유는 같은 조직 안에서만 한다(D-114, 개정 2026-10-25). 근거: 초안 §7·사용자.

<a id="d-24"></a>

- **D-24 워크스페이스 간 참조·공유·이동.** 같은 조직 안에서 모두 포함하고 조직 밖으로는 하지 않는다(D-114, 개정 2026-10-25). 이동 전에 공개 범위·권한 변화를 사용자 id·권한 수준·공개 링크·개별 공유 단위로 확인한다. RLS 복잡성을 이유로 제외하거나 미정으로 되돌리지 않는다(P-R01 기각). 근거: 초안 §7·사용자.

<a id="d-25"></a>

- **D-25 탈퇴와 소유권.** 팀 공간에서 만든 문서는 작성자 탈퇴 뒤에도 남고 관리자가 인계한다. 공유한 개인 원본은 별도 소유권을 유지한다. 근거: 초안 §7.

<a id="d-40"></a>

- **D-40 관리자 열람과 문서별 비공개의 관계.** 관리자는 자기 공간의 비공개 문서도 열람한다. D-20의 비공개 예외는 일반 멤버에 적용되고 개인 노트는 별도 영역·권한이다(D-22). O-21 해소. 근거: 사용자.

<a id="d-49"></a>

- **D-49 개인 노트 공유.** 기본 비공개이며 소유자가 특정 사람에게 읽기·수정 권한을 줄 수 있다. 공유해도 개인 소유를 유지하고 상대 공간의 관리자에게 권한이 따라가지 않는다(D-23). 공유 대상은 나와 같은 조직에 속한 사람이며, 공유 행에 조직을 기록하고 둘 중 하나가 그 조직에서 빠지면 철회한다. 노트 자체는 조직과 무관하게 계정에 남는다(D-114, 개정 2026-10-25). O-02 해소, P-04 기각. 근거: 사용자.

<a id="d-59"></a>

- **D-59 문서 소유와 배치.** 공간 문서의 소유 공간과 위키/모듈 항목 배치를 구분한다. 같은 공간 이동은 권한을, 공간 간 이동은 소유·접근권한·참조 영향을 확인하며 같은 조직 안에서만 한다(D-114, 개정 2026-10-25). 개인 노트는 사용자 소유로 별도 관리한다. O-20 해소. 근거: 사용자.

<a id="d-106"></a>

- **D-106 보관 항목의 자기 댓글 지우기(P-28 현행 유지).** 개인 내용 회수를 위해 본인 댓글 지우기만 허용하며 수정·새 댓글·남의 댓글 지우기로 넓히지 않는다. 보관된 항목·모듈의 업무/문서 권한은 read로 낮아져 소유 권한자도 남의 댓글은 이미 403(42501), 본인은 204이며 목록의 지우기 표시도 같은 권한을 따른다. 수정·스레드 해결·새 댓글은 409다. **권한 변경·403→409 변경이 아니고 코드·SQL도 바꾸지 않는다.** 기존 동작을 고정하는 시험만 추가했다. 읽기 전용의 댓글 금지(D-20)와 별개로 본인 댓글 지우기는 쓰기가 아니라 회수다. 전체 호출 경로·시험은 [제거 전 SQL 정책 계약](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/development.md#version-contract).

<a id="d-111"></a>

- **D-111 조직 테넌트.** 계층은 서버 › 조직 › 워크스페이스 › 모듈 › 항목이다. 모든 워크스페이스는 조직 하나에 속한다. 한 계정은 여러 조직에 속할 수 있고 사이드바 맨 위의 조직 › 워크스페이스 전환기로 오간다. 개인 화면(홈·내 업무·알림함·시간 기록·공유받은 문서·검색)은 현재 조직 범위다. 격리는 같은 DB에서 RLS의 조직 경계로 하며 조직별 DB·스키마는 두지 않는다. 조직 표에는 조직별 IdP 연결 자리(nullable)를 두되 단일 IdP(D-45)를 유지한다. 셀프호스트와 SaaS 모두 같은 모델이다(D-07·D-08). 근거: 사용자(2026-10-25).

<a id="d-112"></a>

- **D-112 역할.** 서버 관리자는 별도 표 `server_admins`에 두고 조직 생성·목록·서버 운영 로그 같은 메타데이터만 다루며 어떤 조직의 내용도 보지 않는다. 초기 서버 관리자는 운영자가 지정한 OIDC 식별자를 시드한다(D-51, X-10 유지). 조직 관리자(`organization_members.role=admin`)는 조직 설정·멤버·워크스페이스 목록·삭제·소유자 이전 같은 메타데이터만 다루고, 내용은 "관리자로 참여"로 자기를 그 워크스페이스의 관리자로 넣은 뒤에만 보며 이 자기 부여는 감사로그에 남는다. 워크스페이스 역할은 관리자·멤버·읽기 전용(`workspace_members.role`)과 소유자(`owner_id`)다. 읽기 전용은 댓글을 포함한 쓰기를 하지 않는다. 조직 안 워크스페이스는 조직 멤버 누구나 만들 수 있고 만든 사람이 소유자·관리자다. 근거: 사용자(2026-10-25).
  - 개정 2026-10-26: 조직 관리자는 삭제된 워크스페이스 복원과 소유권 제안도 한다(삭제·소유자 이전의 짝). 워크스페이스 초대는 워크스페이스 관리자가 보내며, 조직 밖 사람이 수락하면 그 조직의 멤버(`organization_members.role=member`)로 먼저 가입한 뒤 초대받은 워크스페이스 역할을 받고 이 가입은 감사로그에 남는다. 조직 멤버가 느는 경로는 조직 관리자의 추가와 이 초대 수락 둘이다. 근거: 사용자(2026-10-26 ⑦·⑬).

<a id="d-113"></a>

- **D-113 접근 함수 하나.** SQL에 `app_access(kind, id)`를 두어 none/read/write/owner를 돌려주고, 조직 경계·역할·항목 멤버·개별 공유·그룹·보관·삭제를 그 안에서 한 번만 계산한다. RLS·서버 검사·웹 플래그는 접근 등급을 모두 이 결과에서 가져오고 따로 계산하지 않는다. 등급 위에 얹는 추가 조건은 각 결정이 정한 것뿐이다: `allow_copy`와 템플릿 예외(D-115), 보관 상태에서 본인 댓글 회수(D-106), 읽기 전용의 쓰기 금지(D-20). 상위 공유의 상속은 항목·공간 역할이며 부모 문서의 공유는 상속하지 않는다(D-20). 보관된 모듈 아래에서는 항목 자체를 포함해 무엇도 복구하지 못하고 모듈 보관 해제 뒤 복구한다. 근거: 사용자(2026-10-25).
  - 개정 2026-10-26: 보관된 항목에서 워크스페이스 관리자·소유자는 공유·공개 링크·설정을 보관 해제 없이 바꿀 수 있다. 내용 편집·새 댓글·상태 변경은 보관 중 409 그대로다. 이 예외는 등급 위에 얹는 추가 조건 목록에 들어간다. 근거: 사용자(2026-10-26 ⑯).

<a id="d-114"></a>

- **D-114 공유·이동·공개 링크의 조직 경계.** 개별 공유·@참조·이동·복제·개인 노트 공유는 같은 조직 안에서만 한다. 개인 노트는 계정 소유로 조직과 무관하게 남고, 공유 행에 조직을 기록해 둘 중 하나가 그 조직에서 빠지면 철회한다. 역할이 개별 공유의 상한이다. 공간에서 사람을 제거하면 그 공간 문서에 그 사람이 받은 개별 공유와 업무 담당을 해제하고 활동(D-119)에 남기며 확인 대화에 건수를 보인다. 조직에서 빠지면 그 조직의 모든 워크스페이스에서 받은 개별 공유·업무 담당과 조직에 귀속된 공유·참조 전부를 철회한다. 이동 확인은 사용자 id·권한 수준·공개 링크·개별 공유 단위로 변화를 보인다(이름 집합 비교가 아니다). 비로그인 공개 링크는 유일한 조직 밖 출구이며 조직 관리자가 조직 단위로 끌 수 있고 기본은 켜짐이다. 끄면 기존 링크도 응답하지 않는다. 근거: 사용자(2026-10-25).
  - 개정 2026-10-26: 워크스페이스 초대 수락의 조직 자동 가입은 D-112를 따른다. 공유 요청(개별 공유·개인 노트 공유)은 웹이 현재 조직 id를 보내고 두 사람의 공통 조직이 여럿이어도 그 조직을 선택한다. 이 값은 권한의 근거가 아니다. 서버는 D-20·D-113의 공유 권한과 두 사람의 해당 조직 멤버십을 검증하고, 워크스페이스 문서는 그 공간의 조직과도 일치해야 한다. 개인 노트 자체는 계정 소유로 유지하고 공유 행에 검증된 조직을 기록해 위의 탈퇴 시 철회 규칙을 적용한다. 근거: 사용자(2026-10-26 ⑬·⑮), D-20·D-49·D-113·D-114.

<a id="d-115"></a>

- **D-115 복제·내보내기·다운로드 플래그 하나.** 문서의 `allow_copy`가 꺼져 있으면 소유자 외 모든 권한(수정 권한 포함)이 복제·Markdown/PDF 내보내기·첨부 다운로드를 할 수 없다. 템플릿에서 새 문서 만들기는 예외다. D-20·D-75의 "다운로드 허용"은 이 플래그다. 근거: 사용자(2026-10-25).
