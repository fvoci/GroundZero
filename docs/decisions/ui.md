# 결정 기록 · 화면·UI·토큰·표시 설정

[결정 기록 색인](../decisions.md)의 한 주제다. 번호·앵커(`#d-xx`)는 색인 전체에서 고유하다. 아래 "현재 규칙 요약"은 이 주제의 유효한 규칙을 줄인 것이고, 정본은 그 아래 조항이다. 조항 안의 "개정 2026-10-25"는 그날 바뀐 문구이며 이전 문장은 조항의 원문 연결 또는 [개정 전 판](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/decisions.md)에서 본다.

## 현재 규칙 요약

- shadcn-svelte·Tailwind·공통 토큰과 Tiptap을 쓰고 다른 UI 체계·SSR로 바꾸지 않는다(D-66). 브랜드 색은 남색 primary·노랑 secondary를 oklch로만 적는다(D-122).
- 다크 모드는 계정 설정이며 `.dark` 토큰으로만 정한다. 글자 4.5:1·초점 고리 3:1을 시험으로 지킨다(D-109).
- 입력 칸은 `$lib/ui` 컴포넌트, 본문 열은 컨테이너 쿼리, 같은 줄 확인은 초점 이동 규칙, 상태 알림은 미리 그려 둔다. 주 작업 위의 보조 편집 폼은 요약 줄로 접는다(D-110).
- 보기·묶음은 하위 경로(`/tasks/board`, `/t/:taskId`, 항목 묶음, 모듈 달력)이고 URL > 저장한 보기 > 세션이다. 항목은 종류별 첫 묶음과 공통 묶음(업무·문서·일정·기록)으로 나누고 고른 묶음만 그리며, 경로 없이 열면 세션 기억 → 종류별 기본 묶음으로 간다(묶음 선택에는 저장한 보기가 없다, D-121). 조직이 하나면 자동 선택하고 마지막 조직은 서버에 저장한다(D-121). 보기 전환은 단추 묶음이며 좁은 화면에서는 줄바꿈한다(D-121).
- 공간 관리는 `/w/:ws/members|invitations|groups|settings`, 조직 화면은 `/o/:org/members|invitations|workspaces|settings`, 서버 관리는 `/admin/organizations|admins`다. 서버 관리 경로는 샴 가5에서 구현됨. 조직·서버 관리의 기본 경로는 `members`·`organizations`로 바꾸며 탭 전환은 pushState여서 주소로 바로 열고 공유하고 탭 단위로 뒤로 갈 수 있다(D-121).
- 일반 완료는 토스트, 동작 단추가 있는 완료 토스트는 10초 뒤 닫히고 마우스·키보드 초점·창 숨김 동안 멈춘다. 입력 오류는 필드 옆, 저장 실패는 화면 안 메시지, 연결은 닫을 수 있는 배너다(D-82).
- 한국어·영어, IANA 시간대, 주 시작, 12/24시간은 계정에 보존하고 UTC 저장·사용자 시간대 표시다(D-50, D-81).
- Storybook은 합성 데이터로 제품 컴포넌트를 보여 주며 Cloudflare Workers에 공개한다. 화면 스토리는 기본 하나와 375px·어두움·200% 글꼴을 합친 하나를 두고 부품 변형은 만들지 않는다(D-108). 접근성 lint 예외는 위치 한정이다(D-98).

## 조항

<a id="d-50"></a>

- **D-50 시간대 규칙.** 실제 시각은 UTC 저장·사용자 시간대 표시, 날짜 전용 값은 날짜 보존이다. 개인 집계는 사용자 시간대, 공동 반복 일정은 일정의 시간대를 쓴다. O-05 해소. 근거: 사용자.

<a id="d-66"></a>

- **D-66 프론트엔드 UI 구성.** shadcn-svelte(Bits UI)·Tailwind·공통 토큰과 Tiptap을 쓴다. 현재 Svelte·Vite·TypeScript와 호환되는 공식 Vite 수동 설치를 쓰며 다른 종합 UI 시스템을 병행하거나 SvelteKit·SSR로 전환하지 않는다. 달력·간트·칸반 끌기는 별도 조사하며 날짜 선택을 업무 달력으로 보지 않는다. 최초에는 필요한 최소 UI만 `apps/web/src/lib/ui`·`$lib/ui`에 두고 기능별로 복사하지 않는다. 제공 동작·접근성·키보드를 우선하고 디자인은 토큰 중심으로 바꾼다. 실수요 없는 래퍼·범용 폼·자체 모달/메뉴/초점 관리자는 만들지 않는다. 출처·판·명령은 [UI 기록](../../apps/web/src/lib/ui/README.md)에 남기고 수정은 최소화한다. rem·확대 존중·CJK 타이포·키보드/초점/라벨/오류/대화상자 초점복귀를 확인하고 배지 색 외 이름·아이콘을 함께 쓴다. 라이브러리는 검증을 대신하지 않는다. 편집기 없는 체크리스트도 같은 데이터·권한을 쓴다(D-30). 브랜드 토큰은 D-122, 화면 구조 개편은 D-121·D-126이 승인했다. 근거: UI 지침.

<a id="d-81"></a>

- **D-81 표시 언어와 날짜·시간 정책.** 근거: 사용자.
  - 한국어(원본)·영어로 메뉴/폼/오류/알림/달력/접근성/내보내기를 번역한다. 사용자 내용은 번역하지 않는다. Paraglide JS 2와 언어별 메시지 파일(영역별로 나눌 수 있다, 개정 2026-10-25)을 쓰며 변수 치환·복수형을 사용하고 키 누락/불일치는 check가 거부한다. 서버 오류·감사·상태 값은 언어 중립이며 번역문을 DB 상태로 쓰지 않는다.
  - 언어·IANA 시간대·주 시작(월/일)·12/24시간을 따로 골라 계정에 보존한다. 저장값이 우선이고 없을 때만 브라우저 언어/시간대를 제안한다. 주 시작·시각 형식 기본값은 선택 언어 관례다. 브라우저 변경으로 저장값을 덮지 않고 표시 설정으로 일정 시각/날짜를 바꾸지 않는다.
  - 실제 시각은 UTC 저장·전송/사용자 시간대 표시, 날짜 전용 값은 날짜다. 반복 일정은 자체 시간대·현지 시각을 유지한다. 없는 현지 시각의 반복 회차는 건너뛰고 그 사실을 표시하며 겹친 시각은 앞선 한 번만 만든다(RFC 5545 §3.3.10). 단건 생성은 없는 시각을 거부해 다시 고르게 하고 겹친 시각은 앞선 것으로 읽는다. 기존 일정·시간의 편집은 D-93이다.
  - 시간 원본은 나누지 않고 일/주/월 합계만 사용자 시간대 자정으로 나눈다. 일시정지 시각을 저장하지 않으므로 일시정지 시간은 경과 비율로 빼고 나눈 합을 원래 합과 같게 한다. 주 합계는 사용자 주 시작, 타이머 경과는 표시 설정과 무관하다.
  - 모든 날짜 화면(달력/날짜 선택/간트/홈/강의/스터디/시간 기록)은 같은 설정으로 오늘·주·월 경계를 계산한다. 일요일 고정·서버 지역 시간에 기대지 않는다. 공동 일정의 원래 시간대가 다르면 함께 표시하고 `Intl` 위의 작은 공통 포매터를 쓴다.

<a id="d-82"></a>

- **D-82 사용자 피드백 규칙.** 일반 완료는 오른쪽 아래 토스트(모바일 탐색·키보드와 겹치지 않게), 입력 오류는 필드 옆, 저장 실패·충돌은 입력/재시도를 보존한 화면 내 메시지, 연결은 배너, 멘션·초대는 알림함이다. 자동 저장 성공은 편집기 상태에만 표시한다. 일반 완료는 모두 토스트이며 화면 안 완료 문구로 대신하지 않고, 배너에는 닫기 단추를 둔다(개정 2026-10-25). 반복 오류 토스트는 쌓지 않고 갱신한다. 토스트·배너는 aria-live로 알리며 키보드로 닿고 닫혀야 한다. 알림함 규칙은 D-118. 기존 UI·i18n을 쓴다. 근거: 사용자.
  - 동작 단추가 있는 완료 토스트는 10초 뒤 닫히며, 마우스·키보드 초점이 머무는 동안과 창이 숨겨진 동안은 멈춘다(개정 2026-11-01). 근거: 사용자 위임 2026-11-01([#245 6554980085](https://github.com/fvoci/GroundZero/issues/245#issuecomment-6554980085)).

<a id="d-98"></a>

- **D-98 Safari 키보드 접근성과 lint 예외.** 의미에 맞는 요소·초점·접근성 이름·키보드 동작으로 먼저 해결하고 불필요한 role·탭 정지를 추가하지 않는다. 적절한 구현을 막을 때만 해당 위치에 최소 예외와 이유·대안을 남긴다. 전역 lint 완화는 승인하지 않았다. ClashConfirm의 넘치는 값 상자만 이름 있는 region·tabindex=0과 한 줄 예외를 쓰며 짧은 상자는 제외한다. 당시 검증은 jsdom까지, 실제 Safari는 NOT RUN이다. 근거: 사용자(2026-10-22).

<a id="d-108"></a>

- **D-108 Storybook과 Cloudflare Workers 공개 미리보기.** 실제 제품 컴포넌트의 상태를 합성 데이터로 확인하는 Storybook을 둔다. 복제 컴포넌트·Storybook 전용 제품 분기·새 디자인 시스템을 만들지 않고 로그인·API·DB·협업 흐름은 브라우저 회귀 시험(#118)에 남긴다. 정적 빌드는 Cloudflare Workers(정적 자산 Worker `fvoci-storybook`)의 workers.dev에 접근 제한 없이 공개하고, Workers Builds가 main 배포와 PR별 미리보기를 맡는다. 유료 서비스 가입과 제품 앱 배포는 포함하지 않는다. story의 합성 데이터는 풍부하게 두고 개발 seed와 같은 데이터 파일을 쓴다. 사용·설정 기록은 [제거 전 개발 지침의 Storybook](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/development.md#storybook). 근거: 사용자(2026-10-25).
  - 개정 2026-10-27: 스토리 기준. 화면 스토리는 기본 하나와 어려운 조건을 합친 하나(375px·어두움·200% 글꼴)만 둔다. `$lib/ui` 부품은 변형 스토리를 따로 만들지 않고 대비는 D-109의 시험이 맡는다. 넘침·잘림·초점은 브라우저 시험 단언으로 확인하며 스토리를 늘려 대신하지 않는다. 375px는 D-128의 좁은 폭, 200% 글꼴은 WCAG AA 1.4.4와 D-110(2)의 근거로 유지한다. 달리는 아비시니안 오버홀 3단계(#141)에서 이미 만든 변형은 그 PR에서 걷어내지 않고 4단계에서 이 기준으로 정리한다(#150). 근거: 사용자(2026-10-27, #150).

<a id="d-109"></a>

- **D-109 화면 밝기(다크 모드).** 시스템 설정 따르기(기본)·밝게·어둡게를 표시 설정에서 고른다. 선택은 다른 표시 설정(D-50·D-81)처럼 계정(`user_settings.theme`, 기본 `system`, 서버가 system·light·dark만 받는다)에 두어 모든 기기에서 같다. 이 브라우저의 localStorage에는 첫 그림용 사본만 두고 로그인하면 계정 값으로 맞춘다. 계정 저장은 사용자가 백엔드·SQL 수정을 얇은 관통 단위(tracer bullet: DB→서버→OpenAPI→클라이언트→화면 한 줄기, 각 단계 시험 포함, 넓은 리팩터링 없음)로 허가해 넣었다(2026-10-25, "백엔드 SQL등도 트레이서 불릿 형태의 수정 허가"). 통합 기준(D-107) 뒤 첫 추가 마이그레이션 `202610250001`이다. 어두운 색은 shadcn `.dark` 토큰과 Tailwind `dark:` 변형으로만 정하고 다른 테마 체계나 `mode-watcher`를 더하지 않는다. 처음 그리기 전 `index.html`의 짧은 인라인 스크립트가 그 사본으로 같은 규칙을 적용해 깜빡이지 않게 하고(CSP를 도입하면 그 해시를 허용한다), `color-scheme`으로 기본 입력 칸·스크롤바도 맞춘다. 두 테마 모두 글자 4.5:1·초점 고리 3:1(WCAG 2.2 AA)을 시험으로 지킨다. 입력 칸(Input·Textarea·NativeSelect·Select 트리거·Checkbox)의 경계는 전용 토큰 `--input-border`로 바탕·카드·팝오버·muted와 3:1 이상이고(WCAG 1.4.11), 초점 고리(`--ring`)는 쉬는 입력 칸 테두리와 약 2:1 차이가 나게 둔다. 카드·구분선의 `--border`는 장식이라 일부러 3:1보다 옅게 둔다(약 1.3). 이 테두리 결정은 사용자의 지시("사용자(사람)의 사용 경험을 향상시키는 방향으로 적극 진행할 것")에 따라 조정 세션이 정했다(2026-10-25). HWP·PPTX·DOCX 미리보기와 PDF 인쇄는 원본 모양을 지키려 흰 바탕을 유지한다. Storybook은 도구 막대로 밝게·어둡게를 고른다(기본 밝게). 구현 기록: [제거 전 개발 지침의 프론트엔드 UI](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/development.md#ui). 브랜드 토큰은 D-122. 근거: 사용자(2026-10-25, "ui/ux에 다크모드도 추가해"), #133.

<a id="d-110"></a>

- **D-110 화면 다듬기 규칙.** 기능 화면은 다음을 따른다. (1) 입력 칸·여러 줄 칸·선택 상자는 `$lib/ui`의 `Input`·`Textarea`·`NativeSelect`(D-66 CLI로 추가)로 그리고 기능 코드에서 테두리·여백을 손으로 꾸미지 않는다. (2) 본문 안의 여러 열은 창 폭(`md:`·`lg:`) 대신 본문 폭 컨테이너 쿼리로 나눈다(`App.svelte`의 `main`이 `@container`; 대화상자처럼 본문 밖에 그리는 것은 예외). 사용자가 키운 루트 글꼴과 사이드바 폭을 따르기 위해서다. (3) 같은 줄에서 묻는 확인("…할까요? [확인][취소]")은 물을 때 확인 단추로 초점을 옮기고, 그만두면 처음 누른 단추로 돌려주며, 되돌릴 수 없는 동작의 확인 단추는 `destructive`다(`trash/DeleteButton.svelte`, #135의 `features/common/inline-confirm.ts`). 메뉴 항목에서 연 대화상자는 닫을 때 메뉴 단추로 초점을 돌린다. (4) 상태 알림(`role="status"`·`aria-live`)은 처음부터 그려 두고 글만 바꾼다(비었을 때는 `empty:hidden`). 글과 함께 새로 넣으면 화면 낭독기가 놓칠 수 있다.
