# 결정 기록 · 시간 기록

[결정 기록 색인](../decisions.md)의 한 주제다. 번호·앵커(`#d-xx`)는 색인 전체에서 고유하다. 아래 "현재 규칙 요약"은 이 주제의 유효한 규칙을 줄인 것이고, 정본은 그 아래 조항이다. 조항 안의 "개정 2026-10-25"는 그날 바뀐 문구이며 이전 문장은 조항의 원문 연결 또는 [개정 전 판](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/decisions.md)에서 본다.

## 현재 규칙 요약

- 시간 기록은 업무·강의 회차·스터디 단위에서 시작하고 상단 틀에는 "기록 중" 표시와 멈춤만 둔다. 기존 문서·항목·대상 없는 기록은 데이터로만 남는다(D-32, D-117).
- 사용자당 실행 타이머 하나이며 다른 대상에서 시작하면 서버가 진행 중 기록을 멈춰 저장하고 새로 시작한다. 같은 대상이면 이어가기(기본)·새 기록을 묻고 서버는 플래그를 요구한다(D-117).
- 기록은 본인만 본다. 선택 공유 집계는 제거했고 팀 집계는 별도 결정 전까지 없다. 한 건의 길이 상한은 없다(D-117).
- 순공부시간은 강의 시청을 뺀 능동적 공부이고, 실제 수강·휴식·원본 길이·배속 예상 시간을 구분한다(D-32).
- 일·주·월 집계는 사용자 시간대 자정으로 나눈다(D-81).

## 조항

<a id="d-32"></a>

- **D-32 시간 기록.** 시작/일시정지/재개/종료, 업무·강의 회차·스터디 단위 연결, 측정 후 분류, 수동 입력/수정/이력/메모, 일·주·월 집계와 예상/실제 비교를 제공한다. 문서·항목·대상 없는 기록은 데이터로 유지하되 화면의 시작점은 업무·회차·단위 안이다(D-117). 사용자당 모든 조직·공간에서 실행 타이머 하나이며, 다른 대상에서 시작하면 서버가 진행 중 기록을 멈춰 저장하고 새 기록을 시작한다. 앱 종료 뒤 측정 지속·재접속 복구다. 기록은 본인만 보고 집계도 다른 사람에게 보이지 않는다(선택 공유 집계는 D-117로 제거). 순공부시간은 강의 시청을 제외한 능동적 공부다. 실제 인강 수강·휴식·영상 원본 길이·배속 기준 예상 시간을 구분한다. 근거: 초안 §11·사용자; 개정 2026-10-25([원문](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/decisions.md#d-32)).

<a id="d-117"></a>

- **D-117 시간 기록 세 규칙.** (1) 선택 공유 집계(`time_sharing` 설정, 공유 집계 API·화면)를 제거한다. 기록은 본인만 보고 항목·업무 화면에도 내 소요 시간만 보인다. 팀 집계는 별도 결정 전까지 없다. (2) 데이터 모델과 기존 기록(문서·항목·대상 없는 기록 포함)은 유지하되, 화면의 시작 단추는 업무 행·카드·상세, 강의 회차, 스터디 단위 안에만 두고 상단 틀에는 "기록 중" 표시와 멈춤만 둔다. (3) 기록 중에 다른 대상에서 시작하면 서버가 한 트랜잭션에서 진행 중 기록을 멈춰 저장하고 새 기록을 시작한다. 확인 대화는 없고 "이전 기록 저장됨"을 표시한다. (4) 기록 한 건의 길이 상한은 두지 않는다. 기존 긴 기록도 지우거나 자르지 않는다(P-29 기각, #96 닫음). D-32·D-78의 공유 문구를 대체한다. 근거: 사용자(2026-10-25).
  - 개정 2026-10-26: (3)의 보완: 같은 대상으로 기록 중에 다시 시작하면 웹이 "이어가기 / 새 기록"을 묻고 기본 단추는 이어가기다. 서버 시작 API는 같은 대상이 실행 중이면 `continue|new` 플래그가 없을 때 409로 거절한다. 이어가기는 기존 기록을 그대로 두고, 새 기록은 (3)처럼 기존 기록을 멈춰 저장한다. 같은 요청의 재시도는 request_id로 구분한다. 근거: 사용자(2026-10-26 ⑰).
  - 반영 단계: 위 규칙은 확정 요구사항이다. 1단계 SQL(#139), 2단계 서버·OpenAPI(#140), 3단계 클라이언트·재시작 선택 화면(#141)에 걸쳐 반영하며 D-126의 순서로 통합한다. 결정 문서의 병합만으로 main의 타이머 동작이 바뀌거나 각 단계의 구현·검증이 완료됐다는 뜻은 아니다. 근거: 사용자 답변 ⑰·⑲, D-126.
