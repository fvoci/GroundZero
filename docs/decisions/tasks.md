# 결정 기록 · 업무·일정·칸반·간트·상태

[결정 기록 색인](../decisions.md)의 한 주제다. 번호·앵커(`#d-xx`)는 색인 전체에서 고유하다. 아래 "현재 규칙 요약"은 이 주제의 유효한 규칙을 줄인 것이고, 정본은 그 아래 조항이다. 조항 안의 "개정 2026-10-25"는 그날 바뀐 문구이며 이전 문장은 조항의 원문 연결 또는 [개정 전 판](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/decisions.md)에서 본다.

## 현재 규칙 요약

- 업무는 한 단계 하위 업무·복수 담당자·시작/마감·선후행·반복을 가지며 목록/칸반/달력/간트/저장 보기로 본다(D-31).
- 업무 상태는 항목별 사용자 정의이고 범주는 todo·doing·done 셋이다. 기본은 한국어 세 상태 `할 일`·`진행 중`·`완료`이며 모듈 종류에 관계없이 같다. 집계·알림·간트는 범주만 본다(D-116).
- 칸반 이동은 하나의 이동 API, 이동 판(move_version) 조건부 저장, 409 뒤 자동 재전송 없음이다(D-79, D-89).
- 선행 관계는 FS·SS·FF·SF와 0~3650일 지연, 미리보기→승인→저장이며 밀릴 업무가 없으면 저장 뒤 안내한다(D-91, D-125).
- 업무 충돌은 첫 409에서 칸별 값을 고르고, 업무·일정 모두 내가 고친 칸만 최신 판에 적용한다(D-94). 반복 규칙 수정도 기준 판 검사로 409다(D-125).
- 달력은 하나의 조회를 공간→모듈→항목 범위로 쓰고 개인 시간 기록은 넣지 않는다. 기간이 있으면 막대로 그린다(D-80, D-121).
- 간트 머리글은 사용자 주 시작을 따른다(D-90). 일정·시간 편집의 겹친 현지 시각은 선택받는다(D-93).
- 저장한 보기·항목 정보는 기준 판 검사를 거친다(D-103, D-104). CSV 업무는 한 건 원자성, 강의 회차 CSV는 묶음 원자성이다(D-105).

## 조항

사용자 결정(2026-10-23): P-24·P-25·P-26·P-30·P-31 채택, P-28 현행 유지, P-29·P-35 보류·추적이다. P-27·P-32·P-33·P-36 등 나머지를 일괄 채택하지 않았다. 당시 구현·후보 적용 순서는 #97 → #92였으며 이 순서 기록이 새 병합 관문은 아니다. 권한·날짜 경계·판 검사·원자성의 최종 보장은 서버 책임이다.

- **P-29·P-35 보류·추적.** P-29(시간 기록 길이 상한): 이번에 도입하지 않는다. 일정의 366일 상한을 그대로 옮기지 않으며 기존 긴 기록을 지우거나 자르지 않는다. 이미 고친 집계 비용(#55, 감사 S20, 기간 안의 날만 펼침)과 정책상 허용 범위(길이 상한 여부와 값)는 별개이며 후자는 미정이다. P-35(반복 회차 맞추기의 항목별 트랜잭션): 보류한다. 이번 SQL 정리에서 부분 커밋·실패·재시도 의미를 바꾸지 않고 0089의 교착 수정은 유지한다. 남은 잠금 보유 시간 개선은 후속 항목으로 추적한다. 추적 이슈: P-29 fvoci/GroundZero#96, P-35 fvoci/GroundZero#95. 이후 결정(2026-10-25): P-29는 상한을 두지 않기로 기각하고 #96을 닫았다(D-117). P-35는 달리는 아비시니안 오버홀 1단계가 흡수해 #95를 그 단계에서 닫는다(D-126).

<a id="d-31"></a>

- **D-31 업무·일정.** 업무·한 단계 하위 업무, 상태·우선순위·복수 담당자·시작/마감일·태그·체크리스트·예상 시간·마일스톤·선후행 관계·반복 업무, 회의/발표/행사 일정, 목록/칸반/달력/간트·검색/필터/정렬/저장 보기를 제공한다. 업무 완료는 담당자 간 공유하고 강의 이수는 개인별이다. 선행 일정 변경은 영향·충돌을 보여 후속 재배치를 승인받는다. 미완료 반복 업무를 남기고 다음 회차는 원래 일정대로 만든다. 근거: 초안 §10·사용자.

<a id="d-79"></a>

- **D-79 칸반 끌어서 놓기.** 화살표·Alt+방향키를 유지하면서 마우스·터치를 추가하고 열/위치 변경은 하나의 이동 API를 쓴다. 마우스는 6px 이상 움직여야 끌기, 클릭은 열기다. 터치·펜은 손잡이에서만 끌고 카드는 스크롤한다. 낙관적 반영 뒤 실패하면 되돌리고 동시 변경(400)·권한 철회(403)·삭제(404)·보관(409)·네트워크 실패를 알린 뒤 최신 목록·항목을 읽는다. 조건부 이동 충돌은 D-89다. 비기본 정렬에서는 열만 바꾼다. 열은 항목의 상태 정의를 따르고(D-116, 개정 2026-10-25) 자동화는 추가하지 않는다. 근거: 사용자.

<a id="d-80"></a>

- **D-80 달력 범위와 날짜 출처.** 하나의 달력 조회를 공간→모듈→항목 범위로 사용하고 공간 화면에는 모듈·항목 필터를 둔다. 모듈별 일정 사본은 만들지 않는다. 정본 출처는 일정/반복 회차, 업무 시작·마감/향후 반복 업무, 강의 수강 예정일, 스터디 계획일, 연구 제출/수정 마감, 프로젝트 산출물 마감, 취미 연습 일정이다. 강의·스터디는 본인의 개인 계획일 우선, 없으면 공통일을 쓰고 출처를 표시한다. 개인 계획은 본인만, 모든 출처는 항목 접근권한 안에서 보여준다. 개인 시간 기록은 달력에 넣지 않는다. 근거: 사용자.

<a id="d-89"></a>

- **D-89 칸반 이동의 조건부 저장.** 업무별 move_version을 두고 열·위치가 바뀔 때 어느 함수에서든 트리거로 증가시킨다. 필드 version과 분리하며 열 재매김도 이동 판을 올린다. base_move_version이 있으면 행을 잠근 같은 트랜잭션에서 비교해 다를 때 무변경 409 move_conflict+현재 업무를 준다. 재시도·되돌리기는 조건 필수, 409 뒤 자동 재전송 없이 최신 상태를 보여준다. 최초 이동은 무조건 이동(D-79)을 유지한다. 옛 호출 호환 의무만 D-92가 대체했다. 근거: 사용자(2026-10-21).

<a id="d-90"></a>

- **D-90 간트의 주 머리글.** 월·주·날짜 세 줄과 D-81의 사용자 주 시작을 쓴다. 월요일은 ISO 주차/주차 연도(그 주 목요일 연도)+실제 날짜 범위, 일요일은 날짜 범위만 쓰고 낭독기에도 주차 없음으로 알린다. 좁으면 줄이거나 비우고 전체 설명은 낭독기/title에 둔다. ‘10월 1주’나 주차 숫자만 쓰지 않는다. 부분 주는 보이는 열만 차지하며 UTC 자정 일수로 계산해 표시만 바꾼다. 기본 주 시작은 선택 언어 관례다. 근거: 사용자(2026-10-21).

<a id="d-91"></a>

- **D-91 선행 관계의 종류와 지연일.** FS·SS·FF·SF와 0~3650 정수 달력 일 지연을 지원한다. 음수 lead·근무일 달력·시간 단위는 제외한다. 업무 쌍당 한 관계이며 기본값은 FS·0, 후속 목록도 같은 정본을 역조회한다. 근거: 사용자(2026-10-21).
  - 날짜는 하루 전체이며 시작=시작일??마감일, 끝=마감일??시작일이다. A→B의 제약은 FS: B시작≥A끝+1+지연, SS: B시작≥A시작+지연, FF: B끝≥A끝+지연, SF: B끝≥A시작−1+지연이다.
  - 미리보기→명시 승인→저장(D-31). 새로 움직인 선행·고친 관계가 전보다 더 요구하는 만큼만, 여러 관계 중 최대 요구로 뒤로 민다. 기간을 유지하고 이미 충족한 업무는 그대로이며 앞당기지 않는다. 날짜 없음·완료 업무는 옮기거나 그 뒤로 전파하지 않는다. 날짜 없음은 알리고 지어내지 않으며, 밀릴 업무가 없고 날짜 없는 후속만 있으면 저장 뒤 안내한다(미리보기·승인은 다른 업무가 밀릴 때, 개정 2026-10-25). 각 업무의 전후 날짜·원인 관계를 보여준다.
  - 관계 변경은 업무 version을 올리지 않고 move_version은 열·위치만 보호한다. 서버는 저장 트랜잭션에서 관계·업무를 잠근 뒤 재계산해 승인한 업무·날짜가 하나라도 다르면 무변경 409 shift_conflict를 준다. 승인 목록이 빈 저장(옮기지 않기로 함)은 비교하지 않는다. 관계 변경과 승인한 재배치는 한 트랜잭션이다.
  - D-92 후 현재 계약은 predecessors(업무/종류/지연) 응답, schedule-plan 미리보기, 필수 관계 수정 본문+편집 시작 관계 base다. 관계가 바뀌었으면 409 link_conflict다. 옛 predecessor_ids 응답·schedule-preview·본문 없는 PUT은 제거했다. 항목 복제는 종류·지연도 복사한다.
  - 간트 선은 관계별 끝을 잇고 화살표는 선행→후속이다. 선 이름·초점·가리킴 설명을 함께 쓰며 색만으로 구분하지 않는다. 끌어서 관계 만들기는 제외한다.

<a id="d-93"></a>

- **D-93 일정·시간 기록 편집의 원래 끝과 겹친 시각.** 손대지 않은 시작·끝은 저장된 시점·초를 보존한다. 고친 현지 시각이 두 번 존재하면 저장 전 ‘첫 번째 01:30 (UTC−04:00) / 두 번째 01:30 (UTC−05:00)’처럼 순서·UTC 차이를 함께 보여 선택받는다. 끝<시작은 서버가 400으로 거절한다. 구현 해석(사용자 결정 밖): 시간대 변경은 양끝을 고친 것으로 보고, 신규 생성의 겹친 시각은 D-81대로 앞선 것이다. 근거: 사용자(2026-10-22, #78·#72).

<a id="d-94"></a>

- **D-94 업무·일정 충돌 뒤 ‘내 입력으로 다시 저장’.** 내가 고친 칸만 적용하고 나머지는 서버 최신값을 유지한다. 같은 칸을 양쪽이 고쳤을 때의 업무 선택은 아래 개정을 따르며, 일정은 두 값을 보여 덮어쓰기를 확인받는다. 일정의 날짜·시각·시간대·종일은 한 묶음이며 최신 판으로 다시 저장해 또 바뀌었으면 409다. 실패해도 입력을 보존한다. 범위는 업무 상세·일정 대화상자이고 문서 자동 3-way 병합 제외(X-11)는 유지한다. 구현 해석(사용자 결정 밖): 업무 시작/마감/마일스톤도 한 묶음, 담당자는 순서 없는 집합이다. 근거: 사용자(2026-10-22).
  - 개정 2026-11-02: 업무 상세는 첫 409에서 바뀐 칸을 비교하고 칸마다 내 입력·서버 최신 중 고른다. 양쪽이 다르게 바꾼 칸을 맨 위에 미선택으로 두고, 나만 바꾼 칸은 내 입력을 기본으로 고른다. 서버만 바꾼 칸은 서버 값을 유지하는 접힌 확인 목록이며 저장을 막지 않는다. 양쪽 값이 같으면 선택 행에 보이지 않는다. 미선택이 남은 저장은 첫 미선택 칸으로 초점을 옮기고 남은 수를 알린다. 업무 기간은 기존 묶음을 유지하고, 담당·태그는 각각 한 집합으로 고른다. 원래 입력과 후보를 보존하며 자동 재전송하지 않는다. 전체 덮어쓰기 하나로는 칸마다 다른 판단을 할 수 없고, 첫 409에서 바로 고르면 한 단계가 줄어들기 때문이다. 일정·항목 적용은 다음 조각이며 문서 블록·자동 병합은 포함하지 않는다. 근거: #180, 부조종사 설계 승인 [6568773043](https://github.com/fvoci/GroundZero/issues/291#issuecomment-6568773043)(D-131의 화면 설계 위임).

<a id="d-103"></a>

- **D-103 저장한 보기의 동시 수정 보호(P-26 채택).** 기존 수정은 기준 판 검사와 갱신을 같은 트랜잭션에서 필수 수행한다. 오래된 요청·재시도가 최신 설정을 덮지 못하며 충돌은 409+필요한 최신 정보, 웹은 입력 보존이다. 생성과 수정을 구분하고 무조건 덮어쓰는 옛 호환 경로는 제거한다(D-92). P-26의 마지막 저장 우선은 채택하지 않았다.

<a id="d-104"></a>

- **D-104 항목 정보의 동시 수정 보호(P-30 채택).** 적용 필드를 명시하고 모든 해당 수정 경로에 기준 판 검사를 둔다. 오래된 수정은 409, 웹은 입력을 보존하고 최신본 확인·다시 편집을 제공한다. 구현 해석(사용자 결정 밖)의 범위는 제목/설명/공개와 항목 프로필 모두이며 상세 필드는 [제거 전 SQL 정책 계약](https://github.com/fvoci/GroundZero/blob/8349771265af71e70d628bd48abe94f815d8f29c/docs/development.md#version-contract)에 있다. D-94가 항목에 이미 승인된 것은 아니고 이 결정으로 판 검사를 추가한다. 문서 자동 3-way 병합(X-11)·범용 충돌 틀로 확대하지 않는다.

<a id="d-105"></a>

- **D-105 CSV 업무 생성의 원자성(P-31 채택).** 생성 후 별도 수정하는 대신 업무 한 건의 모든 필요한 칸을 서버가 확인해 한 트랜잭션으로 저장한다. 실패에 제목만 있는 업무·일부 관계를 남기지 않고 응답 유실 재시도도 요청 id 멱등 계약으로 중복 생성하지 않는다. 원자성은 업무 한 건이며 CSV 전체 성공/실패로 넓히지 않고 행별 결과 안내를 유지한다. 강의 회차 CSV는 회차 번호가 이어져야 하므로 묶음 전체가 한 트랜잭션이고 추가 수만 돌려준다. 두 규칙의 차이는 의도한 것이다(개정 2026-10-25).

<a id="d-116"></a>

- **D-116 사용자 정의 업무 상태.** 항목마다 상태 정의 표(이름·색·순서·범주)를 두고 범주는 todo·doing·done 셋이다. 새 항목은 모듈 기본 세 상태로 시작한다. 홈 집계·내 업무·기한 알림·간트·검색 필터는 범주만 본다. 칸반 열은 항목의 상태 정의를 따른다(D-79). 상태를 지울 때는 그 상태의 업무를 다른 상태로 옮기는 절차를 거친다. D-33의 "항목별 업무 상태 정의"가 이것이다. 근거: 사용자(2026-10-25).
  - 개정 2026-10-26: 새 항목은 모듈 종류와 무관하게 같은 기본 세 상태 `할 일`(todo)·`진행 중`(doing)·`완료`(done)로 시작한다. 이름은 한국어로 심고 사용자가 바꾸거나 상태를 더하고 지운다(3개 이상 가능). 화면은 정의된 이름을 그대로 보이며 번역하지 않는다. 근거: 사용자(2026-10-26 ⑪·⑭).

<a id="d-125"></a>

- **D-125 세부 통일.** 업무 반복 규칙 수정에 기준 판 검사를 두어 일정 반복처럼 409로 거절한다. 간트 키보드 이동에서 밀릴 업무가 없으면 저장 뒤 안내한다(D-91). 강의 회차 CSV는 묶음 전체 원자성·추가 수 응답을 유지한다(D-105). 실시간 문서의 제목 저장은 최신 판으로 덮어쓰되 바뀐 제목을 입력란에 반영한다. 구형 브라우저 초안 키 변환 코드를 제거한다(P-32). 항목 복구도 부모 보관을 검사한다(D-113). 일반 완료 피드백은 모두 토스트, 배너에는 닫기 단추(D-82). 이탈 취소 패턴을 하나로, 알 수 없는 시간대 대체를 함수 하나로, 검색의 공유 첨부 범위·후보 수를 색인과 SQL에서 같게 한다. 근거: 사용자(2026-10-25).
