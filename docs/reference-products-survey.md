## Focalboard 7.8.9

- 보드 만들기: 빈 보드 / 템플릿 13종(회의 안건, 영업 파이프라인, 개인 업무, 프로젝트 업무, 목표·OKR, 스프린트, 사용자 조사, 경쟁 분석, 콘텐츠 달력, 회고, 로드맵 등). 템플릿 보드는 보기 4개(보드 2·달력·표)와 속성·카드 예제를 함께 만든다.
- 보기: 보드·표·달력(템플릿 보드에서 확인. "Add view" 하위 메뉴가 자동 조작으로 열리지 않아 그 밖의 종류는 미확인). 보기마다 이름, 복제, 지우기. 보기마다 거르기·정렬·묶기·보이는 속성이 따로 저장된다.
- 보드 묶기(Group by): 선택형 속성 아무거나(상태, 우선순위 등). 열마다 색 9가지, 숨기기, 지우기, "+ Add a group". "No Status" 열.
- 열 머리 계산: 개수·빈 값 수·빈 값 비율·고유값 수·합·평균·중앙값·최소·최대·범위·가장 이른/늦은 날짜·날짜 범위. 예: 열마다 예상 시간 합(40·72).
- 거르기: 조건 줄 여러 개(속성 + includes 등 + 값), 보기에 저장. 정렬: 아무 속성. 카드 검색: 입력하는 대로 보드 카드를 거름.
- 카드 만들기: 열의 "+ New", 머리 "New" → 빈 카드 또는 카드 템플릿, 달력 날짜 칸의 "+"(그 날짜가 마감일로 채워짐). 만들면 상세 창이 열리고 제목에 초점.
- 카드 상세: 속성(텍스트·숫자·이메일·전화·URL·선택·다중 선택·날짜·사람·여러 사람·체크박스·만든 시각·만든 사람·마지막 수정 시각·마지막 수정한 사람), 댓글, 본문 블록(텍스트·이미지·구분선·체크박스), 첨부, 메뉴(지우기·링크 복사·카드로 템플릿 만들기).
- 카드 메뉴(보드): 지우기·복제·링크 복사. 옮기기 메뉴 없음(끌기 또는 상태 속성).
- 되돌리기: ⌘Z로 카드 이동을 되돌림(확인).
- 내보내기: 보기를 CSV로, 보드 보관 파일, 설정에서 전체 가져오기·내보내기, 언어·테마.
- 작은 화면: "Mobile web early beta" 안내, 열 가로 스크롤.
- 서버 무응답: 표시 없음, 재개 뒤 밀린 동작이 늦게 반영.

## Kaneo 2.28.3

- 구조: 워크스페이스 › 프로젝트(이름·키, 키는 이름 머리글자로 제안 "작출준"). 업무 번호 `작출준-1`.
- 보기: Backlog(계획됨·보관됨, "모두 이동"으로 보드에 올림), 작업(보드·목록), 캘린더, Gantt. 빈 달력·간트는 "시작일, 마감일 또는 둘 다 추가하세요" 안내.
- 보드 열: To Do·In Progress·In Review·Done. 워크플로 설정에서 열 추가·끌어서 순서·"완료 열" 지정, 사용자 정의 필드(필수 여부), 자동화 규칙(GitHub·Gitea 브랜치 푸시·PR·이슈 이벤트 → 열 이동).
- 만들기: 열 머리 "+" → 만들기 창(상태가 그 열, 제목 초점, 상태·시작일·우선순위·담당·마감일·라벨 칩, "계속 만들기").
- 거르기: 상태·우선순위·담당·마감일·라벨. 정렬: 수동(위치)·만든 날·우선순위·마감일·제목·업무 번호.
- 이동: 끌기(dnd-kit), 키보드 Space로 집기 + 방향키(옆 열로 가지 않음, 낭독기 안내 영어).
- 상세: 오른쪽 패널, 주소 `?taskId`, 상단 칩(상태·우선순위·담당·시작·마감), 라벨, 설명, 첨부, 리소스(링크), 하위 작업, 관계, 댓글, 활동 기록(누가 무엇을 무엇에서 무엇으로, 상대 시각). 열 때 초점이 "작업 삭제"에 감. 제목은 벗어나면 자동 저장.
- 날짜: 고르기 달력이 한국어 화면에서도 영어 월 이름·일요일 시작. 카드 날짜 "Oct 24", 상세 "10월 24일" 섞임.
- 간트: 왼쪽 업무 목록(상태·번호·기간), 기간 선택·이전/다음·오늘로, 막대 끌기로 일정 이동(확인 없음), 시작·마감 가장자리 크기 조정 손잡이(접근성 이름 있음).
- 달력: 시작~마감을 잇는 막대.
- 검색: 사이드바 "검색" 또는 `/` → "작업, 프로젝트, 댓글 검색".
- 프로젝트 설정: 이름·키·아이콘·설명·보드 배경, 업무 가져오기·내보내기, 공개 접근(링크 공유), Calendar feeds(라벨 기준 ICS 구독 링크, 링크만 있으면 제목·설명·날짜를 읽음, 철회 가능), 연동(GitHub·Gitea·GitLab·Discord·일반 웹훅·Slack·Mattermost·Telegram).
- 알림 종(읽지 않은 수), 멤버·초대, 밝기 테마 전환.
- 작은 화면: 열 하나씩 가로 스크롤. 서버 무응답: 먼저 옮기고 표시 없음, 재개 뒤 저장.

## Outline 1.11.0

- 구조: 컬렉션 › 문서 트리(사이드바). 새 문서는 초안으로 만들고 "Publish…"에서 위치(컬렉션·상위 문서)를 고른다. 하위 문서는 사이드바 항목의 "+"로 바로 게시.
- 트리: 현재 문서 강조(`aria-current`)·조상 자동 펼침, 끌어서 옮기기(확인·되돌리기 안내 없음), 메뉴 "Move"(검색으로 대상 찾기, "Move to …" 확인, 완료 알림).
- 문서 아래: "Documents"(하위 문서 목록·새 문서)와 "Backlinks" 탭. 백링크를 누르면 그 링크가 있는 자리(`#d-…`)로.
- 편집기 `/` 메뉴: 제목 1~4(단축키), 작업 목록, 글머리·번호 목록, 이미지·동영상·PDF·첨부, 표, 인용, 코드, 수식(LaTeX), 구분선, 쪽 나눔, 오늘 날짜, 접기 블록·접기 제목, 안내 상자(정보·성공·경고·팁), Mermaid·diagrams.net·PlantUML, 외부 서비스 삽입 40여 종. 블록 끌기 손잡이("Drag to reorder").
- 기록: 오른쪽 패널에 판 목록(날짜·편집/게시), "Highlight changes"(본문 안 바뀐 곳 강조), "Compare to Previous version".
- 문서 메뉴: 즐겨찾기, 구독 해제, 권한, 템플릿으로 만들기, 복제, 게시 취소, 보관, 옮기기, 문서 가져오기, 새 문서, 고정, 댓글, 기록, 통계(Insights), 편집 통계, 나란히 열기, 발표 모드, 내보내기(형식 미확인), 복사, 문서 안 찾기.
- 공유: 워크스페이스 멤버 권한 수준, "Publish to web"(링크 공개).
- 검색: 컬렉션·작성자·게시/초안·기간·제목만 거르기, 관련도 정렬, 본문 낱말은 문장째 보임(한국어 제목·본문 검색 확인).
- 홈: 최근 본·인기·최근 수정·내가 만든. 사이드바: 홈·검색·초안·컬렉션·보관·휴지통·가져오기·초대.
- 인증: 자체 로그인 없음(OIDC 등 필요). 언어 제안 배너(한국어 있음).
- 작은 화면: 사이드바를 메뉴 뒤로, 본문·하위 문서·백링크 탭 그대로.
- 서버 무응답: 표시 없음, 재개 뒤 저장.

### 마. 검색 작성자·제목만: API 변경과 호환성 (구현 전 기록)

- 바꾸는 것: `GET /api/search`에 선택 인자 두 개를 더한다. `author`(`me` 또는 사용자 id, 그 사람이 만든 것만)와 `title_only`(`true`면
  제목에서만 찾음, 본문·첨부 글자·번호는 보지 않음). 응답 형식은 그대로다. 인자를 주지 않으면 지금과 똑같이 동작한다(하위 호환).
- 작성자의 뜻: 각 대상의 `created_by`(문서·업무·항목·일정·파일·기록 모두 있는 열). 마지막으로 고친 사람이 아니다.
- 색인·마이그레이션은 바꾸지 않는다. 색인(`IndexDoc`)에 작성자를 넣으면 기존 색인을 모두 다시 올려야 하고 색인 내용을 만드는
  SQL 함수(`app_system_search_payload`)를 바꾸는 마이그레이션이 필요하다. 대신 이미 있는 방식을 따른다: Meilisearch 후보를 쪽마다 받아
  접근 함수로 거르는 자리(`visible`)에서 같은 사용자 권한(RLS)으로 `created_by`를 확인해 한 번 더 거른다. 그래서 거르기는 좁히기만
  하고 볼 수 있는 범위를 넓히지 않는다.
- 제목만: Meilisearch의 질의 단위 `attributesToSearchOn: ["title"]`(색인 설정 변경 없음). 검색 서비스가 없을 때의 대체 검색은 원래
  제목만 보므로 그대로이고, 작성자 조건은 대체 검색 SQL에도 더한다.
- 한계: 작성자 거르기는 후보(최대 300개, 접근 거르기와 같은 범위) 안에서 한다. 그 사람이 만든 것이 후보 밖에 많으면 일부가
  빠질 수 있다(접근 거르기와 같은 한계). 색인에 작성자를 넣는 방식은 이 한계가 없지만 위 마이그레이션·재색인이 필요해 결정으로 남긴다.
