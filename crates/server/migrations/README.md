# 마이그레이션 읽기와 변경

이 디렉터리의 SQL은 적용 이력 순서로 보관한다. 실행 진입점은
[`db::admin::migrate`](../src/db/admin.rs)의 `sqlx::migrate!("./migrations")`다.
설치 절차는 [셀프호스트 안내](../../../docs/self-hosting.md)를 따른다.

## 적용 순서

- 번호가 붙은 `.sql` 파일을 같은 디렉터리에 두고 번호 순서로 적용한다.
  현재 이력에는 `0020`이 없으며 파일 번호는 연속적이지 않다.
- 새 설치도 `0001`부터 전체 이력을 적용한다. 아래 D-88 파일만 골라 실행하지 않는다.
  앞선 파일이 만든 정의를 뒤의 파일이 사용하거나 바꾸므로 도메인별 파일은 독립 설치 단위가 아니다.
- 기존 설치는 SQLx가 기록한 적용 버전과 체크섬을 바탕으로 이어서 적용한다.
  기존 SQL을 고치면 주석만 바뀌어도 체크섬이 달라진다.

## D-88 전환 파일 지도

새 행의 UUIDv7은 Rust 앱이 만들고 SQL에 명시적으로 넘긴다. 아래는 그 전환의 파일 구성이며,
전체 SQL 정의 목록은 아니다. 상세 규칙과 기존 개발 DB에 대한 영향은
[개발 지침 85.1절](../../../docs/development.md#851-id는-앱이-만든다)에 있다.

| 파일                                                           | 전환 범위                                                             |
| -------------------------------------------------------------- | --------------------------------------------------------------------- |
| [0070_app_ids_core.sql](0070_app_ids_core.sql)                 | 공통 ID 도우미, 계정·세션, 워크스페이스·멤버·그룹·초대                |
| [0071_app_ids_documents.sql](0071_app_ids_documents.sql)       | 문서·트리·공유·참조·리비전 복원·댓글, 문서·업무·항목·모듈 휴지통 넣기 |

## 함수 정의 찾기

같은 이름이 여러 파일에 있어도 적용 이력이나 인자가 다른 서명일 수 있으므로 최초 정의가 현재 정의인 것은 아니다.
저장소 루트에서 이름을 검색하고
번호 순서로 `CREATE`, `CREATE OR REPLACE`, `DROP` 및 전체 인자 목록을 함께 읽는다.

```sh
rg -n --sort path --glob '*.sql' \
  '^(CREATE( OR REPLACE)?|DROP) FUNCTION app_record_document_references\(' \
  crates/server/migrations
```

## 이번 안내의 범위

D-88 전환에서는 실제 배포 전이라는 사용자 지시에 따라 기존 마이그레이션도 수정했으며 체크섬 보존은 요구하지 않았다.
기존 개발 DB의 데이터·볼륨 삭제는 별개이며, 남길 데이터를 확인한 뒤 사용자 확인을 받는다.
체크섬이 맞지 않는 DB의 이력·데이터·볼륨을 자동으로 지우거나 수정하지 않는다.

0070–0075는 이미 도메인별로 나뉘어 있어 이 안내를 위해 합치거나 번호를 바꾸지 않았다.
SQL 파일을 유지하면 기존 적용 이력과 비교할 수 있고 다른 변경과 합칠 때 겹치는 부분도 작다.
Supabase는 [별도 셀프호스트 DB 선택지](../../../docs/self-hosting-supabase.md)이며 Keycloak/OIDC는 유지한다.
설치자는 기존 설치 명령을 사용하고 이 파일 구성을 이유로 RLS를 따로 설정하지 않는다.
